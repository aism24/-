# 鋼材取合最適化アプリ：GAS × GitHub Pages 分離構成

鋼材の切断最適化(在庫優先→端材リレー→新品購入の順で歩留まりを最大化する詰め込み計算)を行う
Webアプリです。計算・Excelインポート/エクスポートは完全にブラウザ内(クライアントサイド)で
完結し、サーバーは不要です。リポジトリ直下の他アプリ(`hot-heart/`、`unso-check/`、
`weld-heat-management/`、`taikai-unei/`)と同じ構成(**GitHub Pagesでフロントエンド配信 +
Google Apps ScriptでJSON API + スプレッドシートをデータストア**)を採用していますが、
このアプリでGASが担うのは「実績記録」という付随機能のみです。

## 構成

```
kozai-toriai/
  index.html   … フロントエンドのHTML(画面構造のみ)
  style.css    … スタイル
  app.js       … 画面ロジック + 切断最適化計算エンジン + Excel入出力(ExcelJSをCDNから読み込み)
                 + GAS APIとの通信処理(fetchでGET/POST、実績記録のみ)
  gas/Code.gs  … GAS側に貼り付けるバックエンドコード(実績記録専用のJSON API)
```

計算ロジックは、元のExcelマクロ(`よろずやAI_Claude.xlsm` Module1)のVBAコードを1:1で
JavaScriptへ移植したものです(在庫優先→端材リレー→新品購入の優先順、歩留まり比較、
端材リレー登録、銀行丸め(round-half-to-even)による端数処理の一致など)。

## アプリの使い方(4ステップ)

1. **Excel雛形をダウンロード** — 基本情報(切断代・つかみ代・最小端材長)、工事名・工事番号
   (プルダウン選択で自動連動)・担当者・使用用途、新品購入尺リスト、在庫材リスト、製品データ表
   が入った雛形をダウンロードします。
2. **記入したExcelをインポート** — 雛形に記入した後、そのファイルをドラッグ&ドロップ(または
   選択)すると自動で読み込まれます。
3. **サイズを選んで計算実行**
4. **結果を編集してExcelダウンロード** — 結果テーブルはブラウザ上で直接編集でき、確定後に
   Excelとしてダウンロードします。ダウンロードと同時に、計算結果のサマリが「実績記録」
   スプレッドシートへ自動的に記録されます(GAS呼び出しが失敗してもダウンロード自体は
   止まりません)。

## 1. スプレッドシートの準備

「鋼材取合い」スプレッドシートに、以下2シートを手動で用意しておきます(このアプリのGASは
シートの自動作成を行いません)。

- **実績記録**(1行=1エクスポート): 記録ID, 記録日時, 担当者, 工事番号, 工事名, 使用用途,
  対象サイズ, グループ数, 在庫材使用本数, 端材リレー使用本数, 新品購入本数, 全体歩留まり,
  端材発生本数, 端材発生長さ合計
- **情報**: A列=工事番号, B列=工事名(他のスプレッドシートからQUERY/IMPORTRANGEで自動反映する
  数式列。GAS側からは読み取り専用として扱い、書き込みません), C列=氏名(空欄でよい。テンプレート
  記入時に新規入力された名前をGASが自動的に追記していきます)

## 2. GAS側(バックエンドAPI)のセットアップ

このアプリのGASは、「鋼材取合い」スプレッドシートに**コンテナバインド**して使います
(`SpreadsheetApp.getActiveSpreadsheet()`で自動的に自分自身を参照するため、`SPREADSHEET_ID`の
設定は不要です)。

1. 「鋼材取合い」スプレッドシートを開き、「拡張機能→Apps Script」を開きます。
2. `gas/Code.gs` の内容をまるごとコピー&ペーストします。
3. 保存後、エディタ上部の関数選択で **`checkSetup`** を選び、▶実行ボタンを押すと、
   「実績記録」「情報」シートが想定通りに存在するか確認できます(問題があればログに出ます。
   自動修正は行いません。初回はスプレッドシートへのアクセス許可を承認してください)。
4. 右上の **「デプロイ」→「新しいデプロイ」** を選択します。
5. 歯車アイコンから種類を **「ウェブアプリ」** に設定し、以下を指定します。
   - **説明**: 任意(例: `api-v1`)
   - **次のユーザーとして実行**: 「自分」
   - **アクセスできるユーザー**: **「全員」**(フロントエンドから匿名でアクセスするため必須)
6. 「デプロイ」をクリックし、表示される **新しいウェブアプリのURL**(`https://script.google.com/macros/s/xxxxx/exec`)をコピーします。
7. **このURLをClaudeとのチャットに貼り付けてください。** `app.js` の `GAS_API_URL` に反映して
   GitHubにpushします。
8. コードを修正した場合は、この新規デプロイを編集し「新バージョン」として更新すればURLは
   変わりません。

### 注意点

- CORSのプリフライト(OPTIONSリクエスト)にGASは対応していないため、`app.js` からのPOSTは
  `Content-Type: text/plain` で送信しています。`application/json` に変更しないでください。
- レスポンスは常にHTTP 200で返り、成否は返却JSONの `status` フィールド(`success`/`error`)で
  判定します。
- 「実績記録」はあくまで付随機能です。GAS_API_URL未設定・GAS側の不調・通信エラー等が
  あっても、テンプレート作成・インポート・計算・Excel出力といったアプリ本来の機能は
  止まりません(それぞれ個別にcatchしてコンソール警告を出すだけにしています)。

---

## 3. フロントエンド(GitHub Pages)のセットアップ

1. `kozai-toriai/app.js` の先頭にある `GAS_API_URL` を、手順2で取得したウェブアプリのURLに
   書き換えます。
2. 変更をリポジトリにコミット・プッシュし、mainブランチに反映します。
3. GitHubリポジトリの **Settings → Pages** を開き、**Source** を `Deploy from a branch`(ブランチ:
   `main`、フォルダ: `/ (root)`)に設定します。
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/kozai-toriai/` で公開されます。

- [ ] Excel雛形をダウンロードできる(工事名プルダウンを選ぶと工事番号が自動表示される)
- [ ] 記入したExcelをドラッグ&ドロップでインポートできる
- [ ] サイズを選んで計算実行し、結果テーブルが表示される(色分け・罫線・グループ区切りを含む)
- [ ] 結果テーブルのセルを直接編集できる
- [ ] 「結果をExcelダウンロード」でファイルがダウンロードされる(色・罫線・A4横印刷設定・
      グループ改ページを含む)
- [ ] エクスポート後、「実績記録」スプレッドシートに1行追加される
- [ ] テンプレートの担当者欄に新しい名前を入れてインポート→エクスポートすると、「情報」
      シートC列にその名前が追記される
- [ ] `GAS_API_URL` を意図的に無効な値にしても、テンプレート作成・インポート・計算・
      Excel出力は問題なく動作する(実績記録だけがコンソール警告付きで失敗する)
