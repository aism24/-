# バスケ大会 運営アプリ：GAS × GitHub Pages 分離構成

「バスケ大会 運営アプリ」を、**フロントエンド（GitHub Pages）** と **バックエンド（GAS API）** に分離した構成です。
リポジトリ直下の「試合記録アプリ」（`hot-heart/`）、`weld-heat-management/` と同じ構成（**GitHub Pagesでフロントエンド配信 + Google Apps ScriptでJSON API + スプレッドシート/Driveをデータストア**）を採用しています。

これまではGASのWebアプリ（`doGet`がHTMLを直接レンダリングし、フロント↔サーバー間は`google.script.run`で通信）をそのまま公開していました。GitHub Pages（別オリジン）からは`google.script.run`が使えないため、この構成ではUIをGitHub Pagesで静的配信し、GASは**JSON専用API**として呼び出す形（fetchでGET/POST）に書き換えています。

**今回の移行は「見た目・機能はそのまま」の1:1移植です。** 情報編集・割り当て・試合結果・２日目作成・個別検索・結果表Excel/速報PDF出力など、既存の全機能をそのまま引き継いでいます。データストア（スプレッドシート・Driveの結果表/PDF保存先フォルダ）も既存のものをそのまま使い、IDは変更していません。

## 構成

```
taikai-unei/
  index.html   … フロントエンドのHTML（画面構造のみ）
  style.css    … スタイル
  app.js       … 画面ロジック + GAS APIとの通信処理（fetchでGET/POST）
  gas/Code.gs  … GAS側に貼り付けるバックエンドコード（JSON専用API）
```

スプレッドシート側の構成（「情報」「Ｇ１」〜「Ｇ４」「２日目決勝側」「２日目２部側」の各シート、大会運営メニュー`onOpen`など）は変更していません。既存のスプレッドシート・既存のGASプロジェクトをそのまま使います。

## 1. GAS側（バックエンドAPI）のセットアップ

**重要: 既存の本番デプロイ（現在チームが使っているURL）は変更しないでください。** 新しいコードは**新規デプロイ**として発行し、十分に動作確認してから、必要に応じて案内を切り替えます。

このアプリのGASは、これまでと同じスプレッドシートに**コンテナバインド**されたまま使います（`SpreadsheetApp.getActiveSpreadsheet()`で自動的に自分自身を参照するため、`SPREADSHEET_ID`の設定は不要です）。`EXPORT_FOLDER_ID`（結果表Excel・速報PDFの保存先フォルダ）も既存の値のままです。

1. 既存のGASプロジェクト（このアプリのApps Scriptエディタ。スプレッドシートを開き「拡張機能」→「Apps Script」）を開きます。
2. `gas/Code.gs` の内容を、既存の `Code.gs` の中身と**まるごと置き換えます**（コピー＆ペースト）。
   - 既存の `Index.html`（HTMLファイル）はもう使わないので、そのまま残しても削除しても構いません（`doGet`から参照しなくなります）。
3. 保存後、右上の **「デプロイ」→「新しいデプロイ」** を選択します（既存デプロイの「編集」ではなく、必ず「新しいデプロイ」を選んでください。これにより既存の本番URLはそのまま残ります）。
4. 歯車アイコンから種類を **「ウェブアプリ」** に設定し、以下を指定します。
   - **説明**: 任意（例: `api-v1`）
   - **次のユーザーとして実行**: 「自分」
   - **アクセスできるユーザー**: **「全員」**（フロントエンドから匿名でアクセスするため必須）
5. 「デプロイ」をクリックし、表示される **新しいウェブアプリのURL**（`https://script.google.com/macros/s/xxxxx/exec` の形式）をコピーします。
6. 初回デプロイ時にGoogleアカウントの承認画面が出るので、権限（スプレッドシート・Driveへのアクセス権限）を許可してください。
7. **このURLをClaudeとのチャットに貼り付けてください。** `app.js` の `GAS_API_URL` に反映してGitHubにpushします。
8. コードを修正した場合は、この新規デプロイを編集し「新バージョン」として更新すれば、URLは変わりません。

### 注意点

- GASのウェブアプリはCORSのプリフライト（OPTIONSリクエスト）に対応していないため、`app.js` からのPOSTは `Content-Type: text/plain` で送信し、GAS側で `JSON.parse(e.postData.contents)` として読み取っています。`application/json` を指定するとプリフライトが発生し失敗するので変更しないでください。
- レスポンスは常にHTTP 200で返り、成否は返却JSONの `status` フィールド（`success` / `error`）で判定します。
- 結果表Excel・速報PDFは、これまでと同様にGAS側でDriveの共有フォルダ（`EXPORT_FOLDER_ID`）にファイルを作成し、そのDrive URLを返します。フロントエンドは受け取ったURLを新規タブで開くだけなので、GitHub Pages（別オリジン）からでも追加の変更なく動作します。
- 大会運営（同席の担当者）向けのチーム内利用を想定しており、認証トークン等は付けていません。
- スプレッドシートの「大会運営」メニュー（初期設定／全体再計算／２日目作成／試合結果リセット）は、このアプリとは独立してこれまでと同じように動作します（`onOpen`・`Code.gs`内の対応する関数は変更していません）。

## 2. フロントエンド（GitHub Pages）のセットアップ

1. `taikai-unei/app.js` の先頭にある `GAS_API_URL` を、手順1で取得した**新しい**ウェブアプリのURLに書き換えます（このステップはClaudeが担当します）。

   ```js
   const GAS_API_URL = "https://script.google.com/macros/s/xxxxx/exec";
   ```

2. 変更をリポジトリにコミット・プッシュし、mainブランチに反映します。
3. GitHubリポジトリの **Settings → Pages** を開きます。
4. **Source** で以下を設定します（`hot-heart/`・`weld-heat-management/`と共通のPages設定がすでにあれば、このステップは不要です）。
   - `Deploy from a branch`
   - ブランチ: `main`、フォルダ: `/ (root)`
5. 保存すると数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/taikai-unei/` で公開されます。ホーム画面に追加（PWA的に）しておくと、アプリのようにワンタップで開けます。

## 3. 動作確認

1. 上記URLにアクセスし、「バスケ大会 運営アプリ」のホーム画面（「大会運営」「個別検索」の2つのボタン）が表示されることを確認します。
2. 「大会運営」を開き、「割り当て」タブで会場ボタン（Ｇ１〜Ｇ４、初日全結果が揃っていれば２日目の2会場も）が表示され、押すと試合の割り当て（開始時間・チーム・審判・TO）が一覧表示されることを確認します。２日目の会場ではさらに「コート1」「コート2」の切り替えができることを確認します。
3. 「試合結果」タブで会場（・コート）を選び、得点を入力して「保存」を押すと記録され、勝者側のセルが黄色くハイライトされることを確認します。フリースロー対決で同点を入れた場合、サドンデス勝者を選ぶ確認ダイアログが出ることを確認します。
4. 「情報編集」タブで「会場名編集」「チーム名編集」から値を変更し「保存」できること、「試合結果リセット」で得点だけがクリアされ会場名・チーム名・審判は変わらないことを確認します。
5. 初日の全結果（グループ最終順位）が揃うと、上部に「２日目作成」バーが表示され、「２日目作成」を押すと２日目の組み合わせ（総当たり・トーナメント）が作成されることを確認します。
6. 「結果表ダウンロード（Excel）」「速報PDF」の各ボタンを押し、数秒後に「〇〇はこちら」リンク／「PDF表示」ボタンが表示され、クリックすると新規タブでファイルが開くことを確認します（Driveの共有フォルダに実際にファイルが保存されていることも確認）。
7. 「個別検索」を開き、チーム名ボタンを押すとそのチームの初日・２日目の予定（試合・審判/TO当番。開始時間の昇順）が表示されることを確認します。

## トラブルシューティング

- **一覧が読み込めない/保存できない**: `GAS_API_URL` が正しいか、GASデプロイの「アクセスできるユーザー」が「全員」になっているかを確認してください。
- **CORSエラーが出る**: `app.js` のPOSTの `Content-Type` が `text/plain;charset=utf-8` になっているか確認してください（`application/json` にするとプリフライトで失敗します）。
- **結果表Excel・速報PDFの作成でエラーになる**: `gas/Code.gs` 内の `EXPORT_FOLDER_ID` が正しいか、GASの初回承認でDriveへの権限を許可したかを確認してください。
- **スプレッドシートの「大会運営」メニューが出ない**: メニューはスプレッドシートを開いたとき（`onOpen`）に作られるため、スプレッドシートを再読み込みしてください。このアプリ（GitHub Pages/GAS API）とは独立した機能です。
