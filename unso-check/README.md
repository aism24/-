# 鳥取運送アプリ：GAS × Vercel 分離構成

運送業者から毎月受け取る配車Excelファイルを取り込み、「21日始まり・20日締め」の締め月ごとに
請求内容をチェックし、年度集計まで行うアプリです。構成は **Vercelでフロントエンド配信(静的ファイル) +
Google Apps ScriptでJSON API + スプレッドシートをデータストア** です。

- 公開URL: https://unso-check.vercel.app/ (Vercelプロジェクト「unso-check」。Root Directory=`unso-check`、Framework=Other)
- 旧URLのGitHub Pages版(https://aism24.github.io/-/unso-check/)も2026-10-21時点で公開中で、mainへのマージで自動更新される
  (リポジトリの方針ではPagesは使わない。止めるかどうかは未定)。
- Vercelへの反映は、指示があったときだけ手動でデプロイする。`vercel.json` の `{"git":{"deploymentEnabled":false}}` で、
  push・マージでは自動デプロイしない。

業務ルールの詳細(締め月ルール、行レベルの検証ロジック、重複判定ルール等)は
「鳥取運送アプリ_引き継ぎ書」(Googleドライブ)を参照してください。

## 構成

```
unso-check/
  index.html   … フロントエンドのHTML(画面構造のみ)
  style.css    … スタイル
  app.js       … 画面ロジック + Excel解析(SheetJS) + GAS APIとの通信処理(fetchでGET/POST)
  gas/Code.gs  … GAS側に貼り付けるバックエンドコード(JSON専用API)
  vercel.json  … push・マージでVercelの自動デプロイを走らせない設定
  to-launcher.js … 「← アプリ一覧へ」ボタン(共通部品のコピー)
```

画面(20日締めチェック・年度集計・工事別内訳・業者別内訳・データ削除)は、起動時にGASの
`getHaulingRawData` で配車データ(集計に使う7列)・締め状態・業者マスタを1回だけ取得し、以降の
絞り込み・集計はブラウザ内(`app.js` の `〜Local` 関数。GAS側の集計関数と同じロジック)で行います。
GASへ書き込むのは、取込み(`importHaulingFile`)・確定(`confirmClosing`)・削除(`deleteConfirmedMonth`)の3つです。

Excelファイル(.xlsm/.xlsx)の解析はブラウザ側([SheetJS](https://github.com/SheetJS/sheetjs)を
CDNから読み込み)で行い、パース済みの行データ(JSON)だけをGAS APIに送信します。GAS側でExcelバイナリ
そのものを扱う必要はありません。マクロ(.xlsmのVBA)は無視し、「配車」シートのセル値のみを読み取ります。

## 1. スプレッドシートの準備

「鳥取運送アプリ」スプレッドシートに、以下3シートを用意します(列名でマッチングするため、
列の並び順は自由です)。**シートが無い場合は、手順2でApps Scriptエディタから `setupSheets`
関数を1回実行すれば自動的に作成されます(業者マスタの初期6社データも自動投入されます)。**

- **配車データ**(統合マスター台帳、1行=1配送): ID, 業者, 締め月, 物件名, 積日, 降日, ブロック,
  節, 積荷, 現場待機, 車種, 最大長さ, 総重量, 通常単価, エキストラ1, エキストラ2, 費用区分,
  費用額, 取込日時, 元ファイル名
- **締め状態**(業者×締め月ごとの確定管理): 業者, 締め月, 状態(未確定/確定済み), 取込日時, 確定日時
- **業者マスタ**: 業者名(1列。初期値: 日本興運・誠和梱包・用瀬運送・川崎クレーン・鳥取グレーン・山陰運送)

## 2. GAS側(バックエンドAPI)のセットアップ

このアプリのGASは、「鳥取運送アプリ」スプレッドシートに**コンテナバインド**して使います
(`SpreadsheetApp.getActiveSpreadsheet()`で自動的に自分自身を参照するため、`SPREADSHEET_ID`の
設定は不要です)。

1. 「鳥取運送アプリ」スプレッドシートを開き、「拡張機能→Apps Script」を開きます。
2. `gas/Code.gs` の内容をまるごとコピー&ペーストします。
3. 保存後、エディタ上部の関数選択で **`setupSheets`** を選び、▶実行ボタンを押します(1回だけ。
   3シート・見出し・業者マスタの初期データが作成されます。初回はDrive/スプレッドシートへの
   アクセス許可を承認してください)。
4. 右上の **「デプロイ」→「新しいデプロイ」** を選択します。
5. 歯車アイコンから種類を **「ウェブアプリ」** に設定し、以下を指定します。
   - **説明**: 任意(例: `api-v1`)
   - **次のユーザーとして実行**: 「自分」
   - **アクセスできるユーザー**: **「全員」**(フロントエンドから匿名でアクセスするため必須)
6. 「デプロイ」をクリックし、表示される **新しいウェブアプリのURL**(`https://script.google.com/macros/s/xxxxx/exec`)をコピーします。
7. **このURLをClaudeとのチャットに貼り付けてください。** `app.js` の `GAS_API_URL` に反映してGitHubにpushします。
8. コードを修正した場合は、この新規デプロイを編集し「新バージョン」として更新すればURLは変わりません。
9. 反映の確認: `{GAS_API_URL}?action=ping` をブラウザで開き、返ってくる `version` が `gas/Code.gs` 冒頭の
   `CODE_VERSION` と一致することを確かめます(コードを直したら `CODE_VERSION` も更新する)。

### 注意点

- CORSのプリフライト(OPTIONSリクエスト)にGASは対応していないため、`app.js` からのPOSTは
  `Content-Type: text/plain` で送信しています。`application/json` に変更しないでください。
- レスポンスは常にHTTP 200で返り、成否は返却JSONの `status` フィールド(`success`/`error`)で判定します。

## 3. フロントエンド(Vercel)の反映

1. `unso-check/app.js` の先頭にある `GAS_API_URL` を、手順2で取得したウェブアプリのURLに書き換えます。
2. 変更をリポジトリにコミット・プッシュし、mainブランチに反映します。`index.html` の `app.js?v=…`・
   `style.css?v=…` の値も変えて、ブラウザに古いファイルが残らないようにします。
3. Vercelプロジェクト「unso-check」へ、mainのコミットを指定して本番デプロイします(指示があったときだけ)。
   Git連携は解除してあり、連携し直す場合も `vercel.json` があるため push・マージでは自動デプロイされません。

## 4. 過去データの移行(初回のみ)

2026年8月20日締め分までの過去データは、既存のGoogleスプレッドシート「運送QUERY2026」の
6社別タブから、`bulkImportLegacy` アクション(確定済みとして取り込む)で一括投入する想定です。
(「運送まとめ」タブは6社統合のはずが実際には1社分のデータしか含まれていない不整合が確認されて
いるため、移行元には使用しません。)

```
POST {GAS_API_URL}
{
  "action": "bulkImportLegacy",
  "company": "山陰運送",
  "rows": [
    { "物件名": "LP京都伏見", "降日": "2026-07-21", "ブロック": "3B2-②", "車種": "10t", "総重量": 7.1, "費用区分": "現場搬入費用", "費用額": 82000 }
  ]
}
```

`bulkImportLegacy` は締め月を降日から自動算出し、業者×締め月ごとに「締め状態」を確定済みとして記録します。
2026年9月20日締め分以降は、通常のExcelアップロード運用(`importHaulingFile`)に切り替えます。

※実データ(2026-10-21確認)では、過去分の多くの行が「降日から算出した締め月」より1〜3か月後の締め月で
記録されています(移行時に、移行元の請求月などで締め月を付けたとみられる)。集計は保存されている「締め月」列の
とおりに行うため、この行は記録された締め月に計上されます。データは修正していません。

## 5. 動作確認

1. 公開URL(https://unso-check.vercel.app/)にアクセスし、ホーム画面が表示されることを確認します。
2. 「Excelファイルを取り込む」から業者の配車Excelファイルを選択し、ファイル名から業者・締め月が
   正しく認識されることを確認します。
3. 対象外行(前月分・来月分の混入)が無ければ取り込まれ、20日締めチェック画面のその業者+締め月へ
   自動で移動し、`配車データ`シートに行が追加されることを確認します。対象外行がある場合は理由付きの
   一覧が表示され、何も保存されないことを確認します。取り込める行が0行のファイルは、画面とGASの両方で
   取り込みません(0行の「未確定」が残ると確定も次の取込みもできなくなるため)。
   同じ業者+締め月(未確定)へ、記録済みと同じ内容を再度取り込もうとすると確認ポップアップが出ます
   (行の並び順・現場待機の書式「6:15」「06:15」の違いは同じ内容とみなす)。
4. 「20日締めチェック」で業者・締め月を選び、工事名別の費用内訳・合計請求額・消費税が表示され
   ることを確認します。「確定する」を押すと `締め状態` シートの状態が「確定済み」になることを
   確認します。
5. 「年度集計」で月別・工事別・業者別の内訳が表示されることを確認します。

## トラブルシューティング

- **一覧や集計が読み込めない**: `GAS_API_URL` が正しいか、GASデプロイの「アクセスできるユーザー」
  が「全員」になっているか確認してください。
- **「ファイル名から業者・締め日を判定できません」と出る**: ファイル名に8桁の日付
  (`YYYYMMDD`)と、業者マスタに登録されている業者名がそのまま含まれているか確認してください。
- **「配車」シートが見つからないと出る**: アップロードしたExcelファイルにシート名「配車」が
  存在するか確認してください。
- **CORSエラーが出る**: `app.js` のPOSTの `Content-Type` が `text/plain;charset=utf-8` になっ
  ているか確認してください。
