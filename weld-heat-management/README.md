# 入熱・パス間温度管理アプリ

鉄骨溶接の**入熱・パス間温度管理**を、現場でiPad/スマホから簡易入力し、履歴を蓄積してPDFで出力できるアプリです。
リポジトリ直下の「試合記録アプリ」と同じ構成（**GitHub Pagesでフロントエンド配信 + Google Apps ScriptでJSON API + スプレッドシート/Driveをデータストア**）を採用しています。

## データ構造(1行=1パスのフラット表)

このアプリは「工事/部材/継手/パス」を別シートに分けず、**1行=1パスのフラットなスプレッドシート**に記録します。
1つの継手(一連の溶接)を記録すると、パスの数だけ行が一括で追加され、各行に工事名・部材・製品名などのヘッダー情報が重複して書き込まれます。

「同じ継手のパスかどうか」は、**「順序」列が1に戻った行を新しい継手の開始とみなす**ルールで判定します(このアプリは1継手分のパスを必ずまとめて連続した行として書き込むため、この判定で正しく区別できます)。

流れ: 「継手情報を入力 → パスごとにスタート/ストップで計測しながら記録 → 溶接完了ボタンでスプレッドシートへ一括保存 → PDF出力」

- 完了ボタンを押すまでは、入力内容はブラウザの`localStorage`(端末内)に自動で一時保存されます。ブラウザが落ちても同じ端末・同じブラウザなら復元できますが、**別の端末には引き継げません**(1つの継手の記録は、開始から完了まで同じ端末で行ってください)。
- 電流・電圧・アークタイム(スタート/ストップの計測時間)・溶接長から、パスごとに入熱量(kJ/cm)を自動計算します。パス間温度・入熱量が管理基準値を外れると自動でNG判定されます。

## 構成

```
weld-heat-management/
  index.html   … フロントエンドのHTML（画面構造のみ）
  style.css    … スタイル（iPad/スマホでの片手入力を想定した大きめUI）
  app.js       … 画面ロジック + GAS APIとの通信処理（fetchでGET/POST）
  gas/Code.gs  … GAS側に貼り付けるバックエンドコード（JSON専用API）
```

## 1. スプレッドシートの準備

以下2枚のシートを用意します。**列の並び順は自由**です(列名でマッチングするため、名前さえ合っていればどこに置いても構いません)。

### シート「入熱パス間記録」(1行=1パス)

以下の列名をすべて含めてください(1行目がヘッダー行)。

```
ID, 工事名, 検査日, 部材, サイズ(幅), 板厚, 部材サイズ, 溶接者, 検査員（入力者）,
層数, パス数, 溶接長, 電流, 電圧, スタート, エンド, アークタイム, パス間温度,
インターバル, 備考, 計測, 製品名, 材質, 溶接方法, 梁成, ウエブ厚, 気温, 順序,
ルートギャップ, 開先角度, image, 積層図,
入熱上限(kJ/cm), パス間温度下限(℃), パス間温度上限(℃), 判定
```

- `ID` はパスごとに1件ずつ自動採番される連番です(空にしておいてください)。
- `判定` 列の見出しに補足説明を追記しても構いません(例:「判定(OK/NG。アプリが自動入力します)」)。アプリ側は列名の前方一致でマッチングするので、`判定`から始まっていれば問題ありません。

### シート「情報」(マスタ選択肢。列ごとに独立したリスト)

以下6列を用意し、それぞれの列にあらかじめよく使う値を何行か入れておくと、アプリ側でプルダウン選択できるようになります(その場での新規追加も可能です)。

```
工事名, 溶接者, 検査員, 部材, 材質, 溶接方法
```

## 2. PDF・写真保存用Driveフォルダの準備

Google Driveに、生成したPDFと撮影した写真を保存するための専用フォルダを1つ作成し、フォルダIDを控えておきます（フォルダを開いたURLの `drive.google.com/drive/folders/【ここがフォルダID】` の部分）。

## 3. GAS（バックエンドAPI）のセットアップ

1. 上記スプレッドシートを開き、「拡張機能」→「Apps Script」で新しいGASプロジェクトを開きます。
2. `gas/Code.gs` の内容をまるごとコピーし、GASエディタの `Code.gs` に貼り付けます。
3. 先頭付近の以下2行を、実際のIDに書き換えます。
   ```js
   const SPREADSHEET_ID = "★ここにスプレッドシートIDを設定してください★";
   const DRIVE_FOLDER_ID = "★ここにPDF・写真保存先DriveフォルダIDを設定してください★";
   ```
4. 保存後、右上の **「デプロイ」→「新しいデプロイ」** を選択します。
5. 歯車アイコンから種類を **「ウェブアプリ」** に設定し、以下を指定します。
   - **次のユーザーとして実行**: 「自分」
   - **アクセスできるユーザー**: **「全員」**（フロントエンドから匿名でアクセスするため必須）
6. 「デプロイ」をクリックし、表示される **ウェブアプリのURL**（`https://script.google.com/macros/s/xxxxx/exec` の形式）をコピーします。
7. 初回デプロイ時にGoogleアカウントの承認画面が出るので、権限（スプレッドシート・Drive・Google Docsの操作権限）を許可してください。PDF出力機能はGoogle Docsを一時的に作成してPDF変換するため、Docsの権限も要求されます。
8. **このURLをClaudeとのチャットに貼り付けてください。** `app.js` の `GAS_API_URL` に反映してGitHubにpushします。
9. コードを修正した場合は、この新規デプロイを編集し「新バージョン」として更新すれば、URLは変わりません。

### 注意点

- 既存の「試合記録アプリ」とは**別のGASプロジェクト・別のスプレッドシート**を使います。
- 複数人が同時に記録を保存しても壊れないよう、ID採番や書き込みは`LockService`で排他制御しています。
- CORSのプリフライト回避のため、POSTは `Content-Type: text/plain` で送信しています（試合記録アプリと同じ方式）。
- レスポンスは常にHTTP 200で返り、成否は返却JSONの `status` フィールド（`success` / `error`）で判定します。
- チーム内利用を想定しており、認証トークン等は付けていません。社外に公開する場合は追加の認証を検討してください。

## 4. フロントエンド（GitHub Pages）のセットアップ

1. `app.js` の先頭にある `GAS_API_URL` を、手順3で取得したウェブアプリのURLに書き換えます。
2. 変更をリポジトリにコミット・プッシュします。
3. リポジトリ直下の `index.html`（試合記録アプリ）と同様に、GitHub Pagesの `Settings → Pages` で `Deploy from a branch` / `main` / `/ (root)` を設定していれば、このフォルダも自動的に配信されます。
4. 公開後、`https://<ユーザー名>.github.io/<リポジトリ名>/weld-heat-management/` でアクセスできます。ホーム画面に追加（PWA的に）しておくと、アプリのようにワンタップで開けます。

---

## 5. 動作確認

1. 上記URLにアクセスし、「🔥 入熱・パス間温度管理」のホーム画面が表示されることを確認します。
2. 「＋ 新しい継手の記録を開始」から継手情報(工事名・部材・製品名・溶接長など、溶接長は必須)を入力し「記録を開始する」をタップします。
3. パス記録画面で、層番号を確認し、「▶ スタート」→ 電流・電圧・パス間温度を入力 → 「■ ストップ」→「✅ このパスを記録」の順に数パス記録し、一覧テーブルに行が追加されることを確認します。基準値を外れた値を入れた場合、警告表示と赤色の行になることを確認します。
4. ブラウザをリロードし、ホーム画面に「▶ 前回の途中から再開する」ボタンが出て、入力途中のパスが復元されることを確認します。
5. 「🏁 溶接完了・スプレッドシートへ記録する」を押し、総合判定（OK/NG）が表示されること、スプレッドシートの「入熱パス間記録」シートにパス数分の行が追加されていることを確認します。
6. 「📄 PDFを出力する」を押し、数秒後に「📄 PDFを開く」リンクが表示されること、リンク先が正しいPDF（工事名・部材・継手情報・パス一覧テーブル）になっていることを確認します。
7. 「📜 履歴を検索する」から、これまでの記録が継手単位で一覧表示され、キーワード検索（工事名・部材・製品名・氏名）で絞り込めること、タップして詳細(パス一覧)を閲覧・PDF再出力できることを確認します。

## トラブルシューティング

- **一覧が読み込めない**: `GAS_API_URL` が正しいか、GASデプロイの「アクセスできるユーザー」が「全員」になっているかを確認してください。
- **PDF出力でエラーになる**: `DRIVE_FOLDER_ID` が正しいか、GASの初回承認でGoogle Docs/Driveへの権限を許可したかを確認してください。
- **CORSエラーが出る**: `app.js` のPOSTの `Content-Type` が `text/plain;charset=utf-8` になっているか確認してください（`application/json` にするとプリフライトで失敗します）。
- **列が見つからないエラー**: 「入熱パス間記録」「情報」シートに、上記の列名がすべて存在するか確認してください（列の順番は自由です）。
