# 入熱・パス間温度管理アプリ

鉄骨溶接の**入熱・パス間温度管理**を、現場でiPad/スマホから簡易入力し、履歴を蓄積してPDFで出力できるアプリです。
リポジトリ直下の「試合記録アプリ」と同じ構成（**GitHub Pagesでフロントエンド配信 + Google Apps ScriptでJSON API + スプレッドシート/Driveをデータストア**）を採用しています。

## 記録の階層構造

```
工事(Projects)
 └ 部材/製品(Parts)  … 部材符号・鋼材種別・板厚
    └ 継手(Joints)   … 継手位置、溶接姿勢・方法・材料、溶接士・検査員、管理基準値(入熱上限・パス間温度上下限)
       └ パス(Passes) … パスごとの電流・電圧・(任意)速度・入熱量(自動計算)・パス間温度・合否判定
```

継手ごとに「記録開始 → パスを都度記録 → 溶接完了で確定 → PDF出力」という流れです。
基準値（入熱上限・パス間温度の上下限）を継手作成時に登録しておくと、各パス入力のたびに自動で合否判定されます。

## 構成

```
weld-heat-management/
  index.html   … フロントエンドのHTML（画面構造のみ）
  style.css    … スタイル（iPad/スマホでの片手入力を想定した大きめUI）
  app.js       … 画面ロジック + GAS APIとの通信処理（fetchでGET/POST）
  gas/Code.gs  … GAS側に貼り付けるバックエンドコード（JSON専用API）
```

---

## 1. スプレッドシートの準備

新しいGoogleスプレッドシートを1つ作成し、以下4枚のシートを作成してください（シート名は完全一致させてください。ヘッダー行は任意ですが、あると分かりやすいです）。

### シート「Projects」
| A: id | B: name | C: createdAt |
|---|---|---|

### シート「Parts」
| A: id | B: projectId | C: code | D: steelType | E: thickness | F: createdAt |
|---|---|---|---|---|---|

### シート「Joints」
| A: id | B: partId | C: position | D: posture | E: method | F: material | G: weldLength | H: welder | I: inspector | J: heatInputLimit | K: tempMin | L: tempMax | M: status | N: createdAt | O: completedAt | P: overallResult | Q: pdfUrl |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

### シート「Passes」
| A: id | B: jointId | C: passNo | D: recordedAt | E: current | F: voltage | G: speed | H: heatInput | I: passTemp | J: judgement | K: note |
|---|---|---|---|---|---|---|---|---|---|---|

いずれも1行目はヘッダー、2行目以降にデータが入ります（appはA列のidを見て自動採番するので、1行目には数値を入れないでください）。

## 2. PDF保存用Driveフォルダの準備

Google Driveに、生成したPDFを保存するための専用フォルダを1つ作成し、フォルダIDを控えておきます（フォルダを開いたURLの `drive.google.com/drive/folders/【ここがフォルダID】` の部分）。

## 3. GAS（バックエンドAPI）のセットアップ

1. 上記スプレッドシートを開き、「拡張機能」→「Apps Script」で新しいGASプロジェクトを開きます。
2. `gas/Code.gs` の内容をまるごとコピーし、GASエディタの `Code.gs` に貼り付けます。
3. 先頭付近の以下2行を、実際のIDに書き換えます。
   ```js
   const SPREADSHEET_ID = "★ここにスプレッドシートIDを設定してください★";
   const DRIVE_FOLDER_ID = "★ここにPDF保存先DriveフォルダIDを設定してください★";
   ```
   - `SPREADSHEET_ID` はスプレッドシートのURLの `/d/【ここ】/edit` の部分です。
   - `DRIVE_FOLDER_ID` は手順2で控えたフォルダIDです。
4. 保存後、右上の **「デプロイ」→「新しいデプロイ」** を選択します。
5. 歯車アイコンから種類を **「ウェブアプリ」** に設定し、以下を指定します。
   - **次のユーザーとして実行**: 「自分」
   - **アクセスできるユーザー**: **「全員」**（フロントエンドから匿名でアクセスするため必須）
6. 「デプロイ」をクリックし、表示される **ウェブアプリのURL**（`https://script.google.com/macros/s/xxxxx/exec` の形式）をコピーします。
7. 初回デプロイ時にGoogleアカウントの承認画面が出るので、権限（スプレッドシート・Drive・Google Docsの操作権限）を許可してください。PDF出力機能はGoogle Docsを一時的に作成してPDF変換するため、Docsの権限も要求されます。
8. **このURLをClaudeとのチャットに貼り付けてください。** `app.js` の `GAS_API_URL` に反映してGitHubにpushします。
9. コードを修正した場合は、この新規デプロイを編集し「新バージョン」として更新すれば、URLは変わりません。

### 注意点

- 既存の「試合記録アプリ」とは**別のGASプロジェクト・別のスプレッドシート**を使います。混同しないよう、デプロイ時の説明欄などに分かる名前（例: `weld-heat-api-v1`）を付けることをおすすめします。
- CORSのプリフライト回避のため、POSTは `Content-Type: text/plain` で送信しています（試合記録アプリと同じ方式）。
- レスポンスは常にHTTP 200で返り、成否は返却JSONの `status` フィールド（`success` / `error`）で判定します。
- チーム内利用を想定しており、認証トークン等は付けていません。社外に公開する場合は追加の認証を検討してください。

---

## 4. フロントエンド（GitHub Pages）のセットアップ

1. `app.js` の先頭にある `GAS_API_URL` を、手順3で取得したウェブアプリのURLに書き換えます。
2. 変更をリポジトリにコミット・プッシュします。
3. リポジトリ直下の `index.html`（試合記録アプリ）と同様に、GitHub Pagesの `Settings → Pages` で `Deploy from a branch` / `main` / `/ (root)` を設定していれば、このフォルダも自動的に配信されます。
4. 公開後、`https://<ユーザー名>.github.io/<リポジトリ名>/weld-heat-management/` でアクセスできます。ホーム画面に追加（PWA的に）しておくと、アプリのようにワンタップで開けます。

---

## 5. 動作確認

1. 上記URLにアクセスし、「🔥 入熱・パス間温度管理」のホーム画面が表示されることを確認します。
2. 「📁 工事一覧・新規記録」→ 工事名を入力して作成 → 作成した工事をタップします。
3. 部材符号などを入力して部材を登録 → 部材をタップします。
4. 「＋ 新しい継手の記録を開始」から継手情報（継手位置は必須、その他任意）を入力し「記録を開始する」をタップします。
5. パス記録画面で電流・電圧・パス間温度を入力し「✅ このパスを記録」を数回タップし、一覧テーブルに行が追加されることを確認します。基準値（入熱上限・パス間温度の上下限）を外れた値を入れた場合、警告表示と赤色の行になることを確認します。
6. 「🏁 溶接完了・記録を確定する」を押し、総合判定（OK/NG）が表示されることを確認します。
7. 「📄 PDFを出力する」を押し、数秒後に「📄 PDFを開く」リンクが表示されること、リンク先が正しいPDF（工事名・部材・継手情報・パス一覧テーブル）になっていることを確認します。
8. 「📜 履歴を検索する」から、これまでの記録が一覧表示され、キーワード検索（工事名・部材符号・継手名・氏名）で絞り込めることを確認します。
9. スプレッドシートを開き、Joints/Passesシートに実際の記録が追加されていること、PDF保存用Driveフォルダに生成されたPDFファイルがあることを確認します。

## トラブルシューティング

- **一覧が読み込めない**: `GAS_API_URL` が正しいか、GASデプロイの「アクセスできるユーザー」が「全員」になっているかを確認してください。
- **PDF出力でエラーになる**: `DRIVE_FOLDER_ID` が正しいか、GASの初回承認でGoogle Docs/Driveへの権限を許可したかを確認してください。
- **CORSエラーが出る**: `app.js` のPOSTの `Content-Type` が `text/plain;charset=utf-8` になっているか確認してください（`application/json` にするとプリフライトで失敗します）。
- **シートが見つからないエラー**: スプレッドシート内のシート名が `Projects` / `Parts` / `Joints` / `Passes` と完全一致しているか確認してください。
