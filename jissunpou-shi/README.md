# 実寸法師：GAS × GitHub Pages 分離構成

案件ごとの鉄骨加工マスターExcel（Googleドライブ）を横断して、**製品マークを検索すると
実寸法（長さ・サイズなど）が表示される**検索アプリです。リポジトリ直下の他アプリ
（`production-management/`、`kozai-toriai/`等）と同じ構成（**GitHub Pagesでフロントエンド
配信 + Google Apps ScriptでJSON API**）を採用しています。

## 構成

```
jissunpou-shi/
  index.html   … フロントエンドのHTML(画面構造のみ)
  style.css    … スタイル
  app.js       … 画面ロジック(製品マークの部分一致検索・ハイライト表示)
                 + GAS APIとの通信処理(fetchでGET、キャッシュ済みデータの取得と手動更新)
  gas/Code.gs  … GAS側に貼り付けるバックエンドコード(集計処理専用のJSON API)
```

## データの流れ

1. 「マスタから実寸法師を開く」スプレッドシートと同じGoogleドライブフォルダに、案件ごとの
   マスターExcel（`(工事名)_マスタのまま.xlsx`。部材1行＝1レコードで、製品マーク・サイズ・
   長さ・本数・重量などを保持）が置かれています。**このアプリはこれらのExcelファイルを
   常に読み取り専用で開き、一切書き込みません。**索引シートは不要で、GASがフォルダ内の
   `.xlsx`ファイルをすべて自動的に列挙します（ファイルが増減しても手動でシートを
   更新する必要はありません）。
2. GASは各マスターExcelを読み込みます。`.xlsx`を直接高速処理できないため、更新（自動または
   手動）のタイミングでのみ、同じフォルダ内に**作業用のGoogleスプレッドシートを作成
   （既存があれば内容だけ上書き）**して変換し、そこから読み取ります（元のExcelファイル本体
   には一切触れません）。
3. 全案件ぶんの部材データは同じフォルダ内の `_cache_jissunpoushi.json` に保存され、通常の
   画面表示はこのキャッシュを読むだけなので高速です（変換・読み込みという重い処理は、更新
   ボタンを押した時、または毎日早朝の自動トリガー時のみ発生します）。
4. フロントエンドは、このキャッシュを一度取得すればあとはブラウザ内で製品マークの部分一致
   検索・ハイライト表示を行います（検索のたびにサーバーへ問い合わせることはありません）。

## 1. GAS側(バックエンドAPI)のセットアップ

このアプリのGASは、「マスタから実寸法師を開く」スプレッドシートに**コンテナバインド**して
使います(`SpreadsheetApp.getActiveSpreadsheet()`で自動的に自分自身を参照するため、
`SPREADSHEET_ID`の設定は不要です)。**このスプレッドシート自体にシートを用意する必要は
ありません**(索引シート不要。案件マスターExcelと同じフォルダに置かれていることだけが前提です)。

1. 「マスタから実寸法師を開く」スプレッドシートを開き、「拡張機能→Apps Script」を開きます。
2. `gas/Code.gs` の内容をまるごとコピー&ペーストします。
3. 左側の「サービス」（＋）から **「Drive API」** を追加します(xlsx→Googleスプレッドシート
   変換に必要な高度なサービスです)。
4. 保存後、エディタ上部の関数選択で **`checkSetup`** を選び、▶実行ボタンを押すと、同じ
   フォルダ内で見つかった案件マスターExcelの一覧がログに出ます(0件ならフォルダ構成を
   確認してください。初回はアクセス許可の承認が必要です)。
5. 関数選択で **`createDailyTrigger`** を選び、▶実行すると、毎日5:00頃に自動更新する
   トリガーが設定されます(初回のみでOKです。任意ですが、案件マスターが随時更新される
   運用なら設定を推奨します)。
6. 右上の **「デプロイ」→「新しいデプロイ」** を選択します。
7. 歯車アイコンから種類を **「ウェブアプリ」** に設定し、以下を指定します。
   - **説明**: 任意(例: `api-v1`)
   - **次のユーザーとして実行**: 「自分」
   - **アクセスできるユーザー**: **「全員」**(フロントエンドから匿名でアクセスするため必須)
8. 「デプロイ」をクリックし、表示される **新しいウェブアプリのURL**
   (`https://script.google.com/macros/s/xxxxx/exec`)をコピーします。
9. **このURLをClaudeとのチャットに貼り付けてください。** `app.js` の `GAS_API_URL` に反映して
   GitHubにpushします。
10. コードを修正した場合は、この新規デプロイを編集し「新バージョン」として更新すればURLは
    変わりません。

### 注意点

- 元のマスターExcelファイルには一切書き込みません(読み取り専用)。変換用の作業用
  スプレッドシート・集計キャッシュ(`_cache_jissunpoushi.json`)・案件ごとの読み込み結果
  キャッシュ(`_records_cache_jissunpoushi.json`。ファイルの更新日時が前回と変わっていない
  案件はここに保存済みの結果を使い回し、変換・再読み込み自体をスキップすることで更新を
  高速化する)は、案件マスターExcelと同じGoogleドライブフォルダ内に作成され、更新のたびに
  同じファイルへ上書きされます(フォルダ内が増え続けることはありません)。
- レスポンスは常にHTTP 200で返り、成否は返却JSONの `status` フィールド(`success`/`error`)で
  判定します。

## 2. フロントエンド(GitHub Pages)のセットアップ

1. `jissunpou-shi/app.js` の先頭にある `GAS_API_URL` を、手順1で取得したウェブアプリのURLに
   書き換えます。
2. 変更をリポジトリにコミット・プッシュし、mainブランチに反映します。
3. リポジトリ直下の `index.html`（アプリ一覧）と同様に、GitHub Pagesの
   `Settings → Pages` で `Deploy from a branch`(ブランチ: `main`、フォルダ: `/ (root)`)を
   設定していれば、このフォルダも自動的に配信されます。
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/jissunpou-shi/` で公開されます。
   ページを開くたびにこのURLの最新版が表示されます(常に最新のコードが動きます)。

## 3. 動作確認チェックリスト

- [ ] ページを開くと、初回は集計が走り(数十秒かかる場合がある)、以降はキャッシュにより
      すぐに表示される
- [ ] 検索欄が空の間は結果テーブルが表示されず、案内文だけが出る
- [ ] 製品マークの一部を入力すると、部分一致(大文字・小文字、全角・半角の違いを無視)で
      該当する部材が一覧表示され、一致箇所が黄色くハイライトされる
- [ ] 同じ製品マークが複数の案件に存在する場合、それぞれ別の行として(案件名付きで)表示される
- [ ] 表に「長さ(実寸法)」「サイズ」「図番」「本数」「重量」等の情報が表示される
- [ ] 「最新化」ボタンを押すと、Excelから再読み込みされ、完了後に画面が更新される(数十秒
      かかる場合があります)
- [ ] 一部のマスターExcelが読み込めない場合でも、画面下部に警告が表示されつつ他のデータは
      問題なく表示される
- [ ] フォルダに新しい案件マスターExcelを追加し「最新化」すると、索引シートを編集しなくても
      自動的に検索対象へ加わる
- [ ] スマホ・iPadで開いても、表が横スクロールでき、レイアウトが崩れない

## トラブルシューティング

- **データが表示されない/エラーになる**: `GAS_API_URL` が正しいか、GASデプロイの
  「アクセスできるユーザー」が「全員」になっているか確認してください。
- **「最新化」が失敗する、または特定の案件が出てこない**: Apps Scriptエディタで「サービス」に
  「Drive API」が追加されているか、GASを実行するGoogleアカウントがそのExcelファイル・
  フォルダを閲覧できるか、`checkSetup`実行時のログでファイルが認識されているか確認して
  ください。
- **列が見つからない/検索してもヒットしない**: マスターExcel側に「製品マーク」「長さ」などの
  見出しが正しく存在するか確認してください(列の順番は自由ですが、見出し文字列は完全一致で
  判定します)。
