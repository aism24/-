# 社内AI(company-ai)— 第1弾 + 第2弾(有給・欠勤)

社内の規程を質問するAI。ログイン(個人Gmail)→ 名簿照合 → 就業規則・別規程に回答 → 👍/👎。答えられない質問と👎は質問ログに溜め、毎朝3時に前日分をクリエーターへメール。

## 構成
- 画面: `index.html` / `app.js` / `style.css` / `config.js`(静的サイト。確認はraw.githack、公開はVercel。`vercel.json`で自動デプロイ停止)
- 頭脳: `gas/Logic.gs`(純粋関数) + `gas/Code.gs`。スプレッドシート「社内AI」にコンテナバインド。
- Gemini: `gemini-3.5-flash-lite` 固定(`Code.gs` 先頭の `MODEL`)。無料枠のため、送るのは質問に関係する条文(最大6件)だけ。実行予算・契約金額に基づく値は扱わない。
- データ: 就業規則PDF(ドライブ)、名簿(B2+B5のOperator。B5は社員No+2000、退職済・退社は除外)、工事・カレンダー(B2)。
- 権限: 名簿のE-Mailに登録された人だけ入れる。管理者シート(氏名・E-Mail・管理者)をE-Mailで名簿に紐づけ、Operator K列に反映。

## GASの設置
1. スプレッドシート「社内AI」→ 拡張機能 → Apps Script。`gas/Logic.gs` と `gas/Code.gs` をそれぞれ全文貼り付け(ファイル名は同じ)。
2. サービス「+」→ **Drive API(v3)** を追加。
3. 設定はすべて「諸情報」シート(A=名前、B=値)に入れる: `DailyReport` `DailyReport建築` `RULES_PDF_ID` `GEMINI_API_KEY` `OWNER_EMAIL` `CLIENT_ID`。`setup` を実行すると、説明(C列)と状態(D列)・「クリエーター用ガイド」シートが作られる。
   ※APIキーがシートに入るため、このシートは作成者・クリエーターだけに共有する。
4. 管理者シートに、クリエーター自身(氏名・E-Mail・「管理者」)を先に入れる(管理者0人だと名簿が更新されない)。
5. エディタで `setup` を実行(シート作成・トリガー: 名簿更新=1時台、メール=3時台)。
6. メニュー「社内AI」→ 名簿を今すぐ更新 → 就業規則を取り込む → 差分を確認 → 就業規則を公開する。
7. デプロイ → ウェブアプリ(実行=自分、アクセス=全員)。発行URLを `config.js` の `GAS_URL`、OAuthクライアントIDを `CLIENT_ID` に入れる。
8. OAuthクライアントID(種類=ウェブアプリ)の「承認済みのJavaScript生成元」に、公開URLのオリジンを追加。

## 就業規則の差し替え
新しいPDFをドライブの同じファイルに差し替える(または `RULES_PDF_ID` を新ファイルのIDに変更)→ メニューで取り込み → 差分(追加/削除/変更)を確認 → 公開。旧版は「規則履歴」シートに残る。条文数が極端に減る場合は公開が中止される。

## 画面確認
`index.html?demo=1` でダミー回答を表示(GAS・ログイン不要)。

## 第2弾: 有給・欠勤の質問(AIを使わず、コードが計算)
- 「私の有給は今年度何日?」「角賢二さんの先月の欠勤」のように、**本人(私・自分)または氏名**がある質問は、就業規則ではなく有給・欠勤データから答える。誰の質問か分からない取得系の質問(例: 有給は何日使えますか)は、従来どおり就業規則で答える。
- データ: 毎晩1時の同期で、B2・B5の `Absenteeism` を「有給欠勤」シートへ合体(B5の社員No・直属上司は+2000、AbIDで重複除外)。取り込み失敗・件数が極端に少ない場合は更新を中止して前回のまま(朝のメールの確認事項に出る)。
- 期間: 指定なし=今年度(4/1〜翌3/31。有給の付与は4月)。「会計年度」(11/21〜)、「今月/先月/N月」(月度=前月21日〜当月20日)、「去年」「2024年度」「これまで」に対応。回答に期間を必ず明記。
- 計算: 有給=1日、半日有給=0.5日、遅早=回数。「至」がある申請は、CompanyCalendarの休日を除いた日数(カレンダーに無い日は土日を休み扱い)。期間外にまたがる分は切り捨て。
- 残日数は、付与日数のデータが無いため算出しない(その旨を回答に出す)。
- 同姓同名・同じ名前が複数いるときは「お一人ずつ質問してください」と返す。
- 生産重量は、次の弾。

## 第2弾: 日報(工数)
- 質問例: 「私の今月の工数」「角賢二さんの先月の作業時間」「ランドポート京都伏見の工数」「私の昨日の日報」「9月25日の◯◯さんの日報」。誰か(私・氏名)か、どの工事(工事名・工事ID・工事No)かが分かる質問だけが対象。分からない質問(所定労働時間など)は就業規則で答える。
- データ: 毎晩1時に、B2(鉄構。1行に最大5件の横長形式)とB5(建設・総務。開始〜終了時刻)の現行DailyReportを、1作業=1行にそろえて「日報」シートへ(日付順。WorkReport Noで重複除外、B5の社員Noは+2000)。作業内容の名前は B2のWorkcontent・B5のSection を「作業内容」シートへ、B5の工事一覧は「工事_建設」シートへ。
- 過去分: メニュー「日報の過去分を取り込む」で、DATA2025.11.21以降 → DATA2024.11.21以降 を「日報_過去」シートへ(現行分と重複しない分だけ。初回と年度替わりに実行)。質問時は日付の列を二分探索し、期間に当たる行だけを読む。
- 期間の既定は今月度(前月21日〜当月20日)。会計年度(11/21〜)・先月・N月・年度・日付指定にも対応。
- 注意: B5の作業時間は開始〜終了の差(休憩は差し引かない)。回答に注記を出す。実行予算・金額は一切扱わない。
- 取り込みに失敗・件数が極端に少ない場合は更新を中止して前回のまま(朝のメールに出る)。

## 会社カレンダーの質問
- 「今日の日付」「今度の土曜は出勤日?」「明日は休み?」「10月12日は出勤日?」「次の休日」「次の出勤日」「次の連休」「今月の出勤日は何日」に、CompanyCalendar(毎晩1時に取り込み。出勤/休日)を使ってコードが答える。
- 曜日・日付は日本時間で計算。カレンダーに登録が無い日は「分からない」と答える。「休日の定義」「休日出勤の手当」など日付の指定が無い質問は、就業規則で答える。
