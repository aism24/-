# 社内AI(company-ai)— 第1弾

社内の規程を質問するAI。ログイン(個人Gmail)→ 名簿照合 → 就業規則・別規程に回答 → 👍/👎。答えられない質問と👎は質問ログに溜め、毎朝3時に前日分をクリエーターへメール。

## 構成
- 画面: `index.html` / `app.js` / `style.css` / `config.js`(静的サイト。確認はraw.githack、公開はVercel。`vercel.json`で自動デプロイ停止)
- 頭脳: `gas/Logic.gs`(純粋関数) + `gas/Code.gs`。スプレッドシート「社内AI」にコンテナバインド。
- Gemini: `gemini-3.5-flash-lite` 固定(`Code.gs` 先頭の `MODEL`)。無料枠のため、送るのは質問に関係する条文(最大6件)だけ。実行予算・契約金額に基づく値は扱わない。
- データ: 就業規則PDF(ドライブ)、名簿(B2+B5のOperator。B5は社員No+2000、退職済・退社は除外)、工事・カレンダー(B2)。
- 権限: 名簿のE-Mailに登録された人だけ入れる。管理者シート(氏名・E-Mail・管理者)をE-Mailで名簿に紐づけ、Operator K列に反映。

## GASの設置
1. スプレッドシート「社内AI」→ 拡張機能 → Apps Script。`gas/Logic.gs` と `gas/Code.gs` をそれぞれ全文貼り付け(ファイル名は同じ)。
2. サービス「+」→ **Drive API(v3)** を追加。
3. プロジェクトの設定 → スクリプト プロパティ: `GEMINI_API_KEY` `CLIENT_ID`(GoogleのOAuthクライアントID) `OWNER_EMAIL`(クリエーターのGmail) `B2_ID` `B5_ID` `RULES_PDF_ID`
4. 管理者シートに、クリエーター自身(氏名・E-Mail・「管理者」)を先に入れる(管理者0人だと名簿が更新されない)。
5. エディタで `setup` を実行(シート作成・トリガー: 名簿更新=1時台、メール=3時台)。
6. メニュー「社内AI」→ 名簿を今すぐ更新 → 就業規則を取り込む → 差分を確認 → 就業規則を公開する。
7. デプロイ → ウェブアプリ(実行=自分、アクセス=全員)。発行URLを `config.js` の `GAS_URL`、OAuthクライアントIDを `CLIENT_ID` に入れる。
8. OAuthクライアントID(種類=ウェブアプリ)の「承認済みのJavaScript生成元」に、公開URLのオリジンを追加。

## 就業規則の差し替え
新しいPDFをドライブの同じファイルに差し替える(または `RULES_PDF_ID` を新ファイルのIDに変更)→ メニューで取り込み → 差分(追加/削除/変更)を確認 → 公開。旧版は「規則履歴」シートに残る。条文数が極端に減る場合は公開が中止される。
