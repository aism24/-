# 実寸法師を開く：GAS × GitHub Pages 分離構成

案件ごとの鉄骨加工マスターExcel（Googleドライブ）を横断して製品マークを検索し、該当する
部材の行をクリックすると、実寸法師(CAD)の図面ファイルが起動する検索アプリです。リポジトリ
直下の他アプリ（`production-management/`、`kozai-toriai/`等）と同じ構成（**GitHub Pagesで
フロントエンド配信 + Google Apps ScriptでJSON API**）を採用しています。

## 構成

```
open_jissun/
  index.html   … フロントエンドのHTML(画面構造のみ)
  style.css    … スタイル
  app.js       … 画面ロジック(検索ボタンでの製品マーク部分一致検索・ハイライト表示・
                 該当行クリックでのCAD起動リンクへの遷移)
                 + GAS APIとの通信処理(fetchでGET、キャッシュ済みデータの取得と手動更新)
  gas/Code.gs  … GAS側に貼り付けるバックエンドコード(集計処理専用のJSON API)
```

## データの流れ

1. 「マスタから実寸法師を開く」スプレッドシートの **「情報」シート**に、案件マスターExcel
   （`(工事名)_マスタのまま.xlsx`）の一覧が手動で用意されています(下記「1. 情報シートの構成」
   参照)。**このアプリはこれらのExcelファイルを常に読み取り専用で開き、一切書き込みません。**
2. GASは「情報」シートに載っているファイルだけを読み込みます。`.xlsx`を直接高速処理できない
   ため、更新（自動または手動）のタイミングでのみ、このスプレッドシートと同じフォルダ内に
   **作業用のGoogleスプレッドシートを作成（既存があれば内容だけ上書き）**して変換し、そこ
   から読み取ります（元のExcelファイル本体には一切触れません）。あわせて、各行の「図番」
   セルに設定されているハイパーリンク（実寸法師の図面ファイルへの絶対パス）も取得します。
3. 全案件ぶんの部材データは同じフォルダ内の `_cache_jissunpoushi.json` に保存され、通常の
   画面表示はこのキャッシュを読むだけなので高速です（変換・読み込みという重い処理は、更新
   ボタンを押した時、または毎日早朝の自動トリガー時のみ発生します）。
4. フロントエンドは、このキャッシュを一度取得すればあとはブラウザ内で製品マークの部分一致
   検索・ハイライト表示を行います（「検索」ボタンを押した時、またはEnterキーで検索します。
   入力するたびには検索しません）。該当行をクリックすると、その部材の図番に設定されている
   CAD起動リンク(`file://...`)へ遷移します。

## 1. 「情報」シートの構成(1行目が見出し。手動で用意する)

| 列 | 内容 |
|---|---|
| A | No(参考情報。アプリのロジックでは使用しない) |
| B | ファイル名 |
| C | URL(案件マスターExcelファイルへのGoogleドライブ共有リンク) |
| D | 工事番号(正式な工事番号) |
| E | 工事名(正式な工事名) |
| F | マスタ場所(例: 鳥取/姫路) |
| H | 表示工事番号 |
| I | 表示工事名 |

ファイル名またはURLが空の行は無視されます。同じ工事番号に複数のファイル（例: 加工先違い）が
紐づいていても構いません。L:M列などにある別の「工事番号→工事名」一覧はこのアプリでは使用
しません。

H:I列(表示工事番号・表示工事名)には、案件マスターExcelがある工事番号・工事名の一覧を
`=SORT(UNIQUE(FILTER(D2:E, D2:D<>"")), 1, TRUE)` のような数式で用意しておきます。この一覧は
アプリのヘッダーに「検索可能な工事一覧」として常時表示されます(集計キャッシュとは別に、毎回
シートから直接読み直すため、数式の結果を変更すればすぐ画面に反映されます)。

## 2. GAS側(バックエンドAPI)のセットアップ

このアプリのGASは、「マスタから実寸法師を開く」スプレッドシートに**コンテナバインド**して
使います(`SpreadsheetApp.getActiveSpreadsheet()`で自動的に自分自身を参照するため、
`SPREADSHEET_ID`の設定は不要です)。

1. 「マスタから実寸法師を開く」スプレッドシートを開き、「拡張機能→Apps Script」を開きます。
2. `gas/Code.gs` の内容をまるごとコピー&ペーストします。
3. 左側の「サービス」（＋）から **「Drive API」** を追加します(xlsx→Googleスプレッドシート
   変換に必要な高度なサービスです)。
4. 保存後、エディタ上部の関数選択で **`checkSetup`** を選び、▶実行ボタンを押すと、「情報」
   シートから読み取れた案件マスターファイルの一覧がログに出ます(0件なら「情報」シートの
   B・C列(ファイル名・URL)が入力されているか確認してください。初回はアクセス許可の承認が
   必要です)。
5. 関数選択で **`createDailyTrigger`** を選び、▶実行すると、毎日5:00頃に自動更新する
   トリガーが設定されます(初回のみでOKです。任意ですが、案件マスターが随時更新される
   運用なら設定を推奨します)。
6. 右上の **「デプロイ」→「新しいデプロイ」** を選択します。
7. 歯車アイコンから種類を **「ウェブアプリ」** に設定し、以下を指定します。
   - **説明**: 任意(例: `api-v1`)
   - **次のユーザーとして実行**: 「自分」
   - **アクセスできるユーザー**: **「全員」**(フロントエンドから匿名でアクセスするため必須)
8. 「デプロイ」をクリックし、表示される **新しいウェブアプリのURL**
   (`https://script.google.com/macros/s/xxxxx/exec`)をコピーします。
9. **このURLをClaudeとのチャットに貼り付けてください。** `app.js` の `GAS_API_URL` に反映して
   GitHubにpushします。
10. コードを修正した場合は、この新規デプロイを編集し「新バージョン」として更新すればURLは
    変わりません。

### 注意点

- 元のマスターExcelファイル・「情報」シートには一切書き込みません(読み取り専用)。変換用の
  作業用スプレッドシート・集計キャッシュ(`_cache_jissunpoushi.json`)・案件ごとの読み込み
  結果キャッシュ(`_records_cache_jissunpoushi.json`。ファイルの更新日時が前回と変わって
  いない案件はここに保存済みの結果を使い回し、変換・再読み込み自体をスキップすることで
  更新を高速化する)は、このスプレッドシートと同じGoogleドライブフォルダ内に作成され、
  更新のたびに同じファイルへ上書きされます(フォルダ内が増え続けることはありません)。
- レスポンスは常にHTTP 200で返り、成否は返却JSONの `status` フィールド(`success`/`error`)で
  判定します。
- **CAD起動リンクについて(重要)**: 図番セルのハイパーリンクは `file://192.168.1.2/share/...`
  のような社内LAN上のファイルサーバーへの絶対パスです。このリンクは**社内ネットワークに
  接続され、かつ該当ファイル形式(`.tdf`等)に実寸法師が関連付けられた端末のブラウザ**でしか
  開けません(社外からのアクセスや、関連付けの無い端末では失敗します)。また、ブラウザの
  種類・設定によって`file://`リンクの扱いが異なる場合があるため、実際の利用端末で該当行の
  クリック動作を必ず確認してください。図番セルにハイパーリンクが無い行(図面未作成)は、
  「備考」欄に「図面作成未完」と表示され、クリックしてもポップアップで案内されます。

## 3. フロントエンド(GitHub Pages)のセットアップ

1. `open_jissun/app.js` の先頭にある `GAS_API_URL` を、手順2で取得したウェブアプリのURLに
   書き換えます。
2. 変更をリポジトリにコミット・プッシュし、mainブランチに反映します。
3. リポジトリ直下の `index.html`（アプリ一覧）と同様に、GitHub Pagesの
   `Settings → Pages` で `Deploy from a branch`(ブランチ: `main`、フォルダ: `/ (root)`)を
   設定していれば、このフォルダも自動的に配信されます。
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/open_jissun/` で公開されます。
   ページを開くたびにこのURLの最新版が表示されます(常に最新のコードが動きます)。

## 4. 動作確認チェックリスト

- [ ] ページを開くと、初回は集計が走り(数十秒かかる場合がある)、以降はキャッシュにより
      すぐに表示される
- [ ] ヘッダーに「検索可能な工事一覧」(「情報」シートH:I列)が表として表示され、ロゴ・
      アプリ名・「最新に更新」ボタンと一緒にページ上部へ固定される(スクロールしても隠れない)
- [ ] 検索欄が空の間は結果テーブルが表示されず、案内文だけが出る
- [ ] 製品マークの一部を入力して「検索」を押す(またはEnterキー)と、部分一致(大文字・小文字、
      全角・半角の違いを無視)で該当する部材が一覧表示され、一致箇所が黄色くハイライトされる
- [ ] 表に「マスタ場所」「工事番号」「工事名」「図面番号」「製品名」「建方日」「ブロック」
      「加工日」「備考」が表示される
- [ ] 図番にCAD起動リンクがある行をクリックすると、実寸法師(CAD)が起動して図面が開く
      (社内ネットワーク・関連付け済み端末で確認すること)
- [ ] リンクが無い行(「備考」欄が「図面作成未完」)をクリックすると、ポップアップで案内されるだけで
      画面は変わらない
- [ ] 「建方日」「加工日」は実際の日付が入っている行では和暦「R◯年◯月◯日」形式で表示され、
      日付になっていない行(「*」等)は元の文字列のまま赤文字で表示され、「備考」欄に
      「建方日の日付不明」または「加工日の日付不明」と追記される
- [ ] 「建方日」「加工日」の列幅は同じ、テーブルの全項目は中央揃えで表示される
- [ ] 「最新に更新」ボタンを押すと、Excelから再読み込みされ、完了後に画面が更新される(数十秒
      かかる場合があります)
- [ ] 一部のマスターExcelが読み込めない場合でも、画面下部に警告が表示されつつ他のデータは
      問題なく表示される
- [ ] スマホ・iPadで開いても、表が横スクロールでき、レイアウトが崩れない

## トラブルシューティング

- **データが表示されない/エラーになる**: `GAS_API_URL` が正しいか、GASデプロイの
  「アクセスできるユーザー」が「全員」になっているか確認してください。
- **「最新化」が失敗する、または特定の案件が出てこない**: Apps Scriptエディタで「サービス」に
  「Drive API」が追加されているか、「情報」シートのB・C列(ファイル名・URL)が正しいか、GASを
  実行するGoogleアカウントがそのExcelファイル・フォルダを閲覧できるか、`checkSetup`実行時の
  ログでファイルが認識されているか確認してください。
- **行をクリックしてもCADが起動しない**: 社内ネットワークに接続されているか、`.tdf`(または
  対象の拡張子)に実寸法師が関連付けられているか、ブラウザが`file://`リンクのクリックを
  ブロックしていないか確認してください。「備考」欄が「図面作成未完」の行はそもそもリンクが
  無いため起動しません。
- **列が見つからない/検索してもヒットしない**: マスターExcel側に「製品マーク」「図番」などの
  見出しが正しく存在するか確認してください(列の順番は自由ですが、見出し文字列は完全一致で
  判定します)。
