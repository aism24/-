# 鳥取工場 生産状況(前日出来高・生産遅れリスト)

鳥取工場の「前日出来高」と「生産遅れリスト」を表示し、PDFでダウンロードするウェブアプリ(iPad対応)。
データの元は、生産管理ダッシュボード(`production-management/`)と同じ索引スプレッドシート「Excelマスタ一覧」と各案件マスター。

## 使い方(2026-11-11 ユーザー指定)
1. アプリを開く(「加工結果を送ってください」だけが出る。GASはまだ呼ばない)
2. 加工結果PDF(例: 261110_加工結果.pdf)を画面のどこかにドロップするか、「フォルダから選ぶ」で選ぶ。PDFの「鳥取工場 加工予定表」のページ(月〜土の6列、件名|製品名|台数|重量|図番)をブラウザの中で読み取り、GASの「予定表」シートへ保存する
   読み込み中は進捗バー(PDFの読み取り0〜15%→照らし合わせ15〜80%=GASの待ち時間に応じて少しずつ→PDF作成80〜100%=予定表のページごと)と「※ﾏｽﾀｰﾃﾞｰﾀにある製品より実寸リンク作成」を出し、PDFができてから一覧の画面に切り替える(2026-11-12)
3. 左=生産遅れリスト、右=前日出来高(結果重量)を見本のPDFと同じ形で並べて表示。取込のお知らせは画面中央(ピンク背景・黒の太字)に出し、OKを押すまで消えない(2026-11-12)
4. 一覧が出たら、そのままPDFをダウンロード(2026-11-12。Excelはやめた): 1ページ目=A4縦の遅れ・結果の表(画面と同じ)、2ページ目以降=取り込んだPDFの「加工予定表」のページ(A4横。製品ごとに「台数」のセルの色を 製品名・重量・図番 のセルにも塗る=どれがまだか分かるように。台数が色なしなら白。ページは216dpiの絵にして塗る。塗れなければ元のページをそのまま)。マスタに加工日(結果の日まで)があるのに台数が青くない行は、台数・製品名・重量・図番を薄い青で塗り、件数を読み込み時のお知らせに「マスタで完了を確認：◯件」と出す(2026-11-12。加工日はGASが予定表の製品ごとに返す planDone)。予定表のページの図番・製品名のセルには、実寸法師へのハイパーリンク(shipping-list-link のマスタ。図番+製品名の完全一致。重複は付けない)を付ける。見た目は変えない。マスタは shipping-list-link のGAS(`?action=links`)を読むだけ(向こうの記録・保存は動かない)。読めなければリンクなしでダウンロードし、お知らせを出す(2026-11-12。261110_加工結果.pdf で116行・232リンク)。グラフと予定重量・結果重量のページは入れない。ファイル名は「取り込んだファイル名_新_YYYYMMDD_HHMMSS.pdf」(ダウンロードした日時。重複防止。2026-11-12)。画面のボタンは「略称設定」と「リセット」(一覧を消して開いた直後の画面に戻す)だけ。ヘッダーはアプリ名=中央・会社ロゴ=右端で、スクロールしても残る。基準日・結果の日はヘッダーの下の右端(2026-11-12)。画面(幅761px以上)は、ヘッダー・基準日・ボタン・表の題名と見出しの行(物件名…)を固定し、表の中だけスクロールする(左右の表は別々にスクロール)。総遅れ合計・総結果合計の行は tfoot を sticky にして、表の枠の最下部に固定(最後までスクロールすると本来の位置)。スマホ幅は画面ごとスクロールし、表は画面の高さまで。表の説明文は出さない

## 決まり
| 項目 | 決まり |
|---|---|
| 対象 | 案件マスターの「加工先」= 鳥取 の行だけ |
| 予定日 | **読み込んだ週間予定表の、製品が載っている曜日の列の日付**。備考①は使わない(加工予定日とは限らず、加工すると加工日と同じ日付に書き換えられているため) |
| 何日の結果か | PDFの「鳥取工場MM.DD結果重量」の日付で決める(2026-11-11 ユーザー指定)。その日=前日出来高の日、次の営業日=基準日(遅れの数え終わり)。いつ読み込んでもそのPDFの日の一覧になる(遅れは、結果の日までに加工日が入ったものだけ加工済みとみなす)。結果の表が無いPDFは今日を基準にする。年はファイル名の先頭 YYMMDD → 予定表の更新日 → 今日 の順 |
| 生産遅れ(左) | 予定表で予定日が**今週の月曜より前**(先週までの予定の取り残し=「先週の漏れ」)で、案件マスターに加工日(X列)が無い製品。今週の予定は遅れにしない。予定日が2か月より前のものは出さない |
| 遅れ日数 | 予定日の翌日から今日まで(今日を含む)の出勤日の数(営業日) |
| 前日出来高(右) | 加工日 = 結果の日(PDFの「MM.DD結果重量」の日)の製品。右端に「備考」: 予定表の予定日より後に加工した(=遅れていた分を加工した)行だけ「11/5予定分対応」と入れて薄い緑にする。それ以外は空欄(2026-11-12。予定日はGASが予定表シートから 工事番号+製品名 → 略称+製品名 で引き、前日出来高シートの「予定日」列にも書く) |
| 今週分が無いとき | 最後に読み込んだ予定表に、今週の月曜〜前の営業日の出勤日が無ければ「11/9(月)と11/10(火)の予定が含まれていないので、予定通り完了したものと考えます」と表示 |
| 物件名 | 週間予定表の件名(略称。例: ITM)だけを表示(2026-11-11 ユーザー指定)。前日出来高は工事番号から略称を引く(未設定ならファイル名) |
| 略称の対応 | 「略称」シート(略称→工事番号)。新しい略称(予定表・加工結果の表のどちらでも。例: LP京都)が出たら画面の「略称設定」で工事番号を選ぶ。案件マスターは「工事番号+製品名」で探す(同じ工事番号の全ファイル) |
| 並び | 物件名 → 部位(柱→大梁→小梁→その他)→ 案件マスターの行の順。生産遅れは物件名 → 予定日の古い順(同じ日は前の並び。2026-11-12、画面で並べ替え)。物件ごとに合計行「【略称】　遅れ合計」、最後に総合計(濃い色) |
| 重量 | 小数第3位を四捨五入して2桁。合計は四捨五入した値の和(見本と同じ) |
| 加工結果の確認 | PDF2ページ目の「鳥取工場MM.DD結果重量」の表の製品に、案件マスターの加工日が入っているか確かめる(日付の入れ忘れに気づくため。2026-11-11 ユーザー指定)。無ければ ① その工事の案件マスターだけを更新日時に関係なく読み直す(作業用データが古い場合)② もう一度確かめる ③ それでも無ければ「マスターデータに日付が入ってません」のポップアップに 製品名|行数(マスターの行番号)を略称ごとに出す。結果の表の無いPDFでは確かめない |
| 同じ製品を何度も読み込んだとき | 物件名+製品名ごとに、新しく読み込んだ予定日で上書き |

週間予定表の台数セルの色(青=加工済み、黄・無色=未完)は読まない。完了・未完は案件マスターの加工日で判定する(1110結果.pdf の116行で、色と加工日の有無がすべて一致することを確認)。
PDFは文字の読めるもの(Excelから書き出したもの)に限る。用紙を回転させたPDF・1文字ずつ分かれた文字にも対応。

## ファイル
- `index.html` / `app.js` / `style.css`: 画面(静的ページ)。PDFはブラウザで作る(1ページ目は表をcanvasに300dpiで描いた画像、予定表のページは pdf-lib で元のPDFから写す)
- `manual/manual.pdf`: ダウンロードPDFの説明書(A4横2ページ。開いた直後・リセット後の画面の黄色いボタンで開く)。元は `manual/manual.html`(表は架空の見本。公開リポジトリのため実データは載せない)。直したらPlaywrightで A4横・背景ありでPDFにし、index.html のリンクの `?v=` を上げる(2026-11-12)
- `sample.json`: GASのURLが未設定のとき(または `?demo=1`)に出すサンプル(実データではない)
- `gas/Code.gs`: GAS(新しいスプレッドシート「鳥取工場生産状況周知」に紐づけて使う)
- `gas/appsscript.json`: GASの設定の参考(時間帯 Asia/Tokyo・Drive API v3)
- `to-launcher.js`: 「← アプリ一覧へ」ボタン(正本は `docs/to-launcher/`)。普段は非表示で、左上の会社ロゴを1.5秒以内の間隔で5回タップすると、その端末だけ表示(ブラウザに記憶)。もう一度5回で消える(2026-11-11、ユーザー指示。truck-fax と同じ仕組み)
- `vercel.json`: push・マージでVercelのビルドを走らせない

## 仕組み(2026-11-11 見直し)
1. 画面がPDFの「鳥取工場 加工予定表」と「MM.DD結果重量」の表を読み取り、GASへ送る(doPost `schedule`)。
2. GASは予定表と加工結果の表に出てくる件名(略称)のファイルだけを読む(加工結果の表だけに出てくる工事=予定表に無い工事を加工した場合も読む。2026-11-12): ① ファイル名(拡張子なし)が略称と同じファイル(ITM → ITM.xlsx)② 無ければ「略称」シートの工事番号のファイル。
   更新日時が前回と同じなら読み直さない。Excelは一時的にスプレッドシートへ変換して読み、すぐ削除する(元のExcelには触れない)。
   生産管理ダッシュボードが作る `_作業用_…` は使わない(ファイル名が最初に変換したときのままで、索引の行と確実に結び付けられないため)。
3. 一覧(生産遅れ・前日出来高)を作り、結果重量の表の製品に加工日が入っているか確かめて返す(無ければその工事だけ読み直して再確認)。
4. 1回のリクエストの中では、各シート・索引・スクリプトのプロパティを1回だけ読み、書き込みはまとめて行う(`cx_`)。
   取込1回あたりのシートの読み書き: 226回 → 64回(初回)、181回 → 47回(2回目以降)(模擬環境で計数)。
5. 自動更新(毎朝・1時間ごと)は使わない(一覧はPDF取込時に作るため)。以前の版の予約は `setupSheets` で消える(動いても予約を消すだけ)。
6. 1回の実行は240秒まで。読み切れなかった案件は1分後に自動で続きを読む。

## シート
| シート | 中身 |
|---|---|
| 予定表 | 読み込んだ週間予定表(物件名・製品名・図番・予定日・数量・重量・読込日時・ファイル名) |
| 略称 | 略称→工事番号(画面で選んで保存) |
| 情報 | A列=項目、B列=値。`索引スプレッドシート`(URLかIDを貼る)・`対象拠点`(鳥取)・基準日・前の営業日・最終更新・未取込の案件・注意 |
| 前日出来高 | 工事名・製品名・図番・重量(t)・生産日 |
| 遅れリスト | 工事名・製品名・図番・重量(t)・生産予定日・遅れ日数(営業日)(遅れ日数の大きい順→予定日の古い順) |
| 取込データ(非表示) | 案件ごとの鳥取の行 |
| 状態(非表示) | 案件ごとの元ファイル更新日時・取込日時・行数・エラー |
| 記録 | 加工結果PDFを取り込んだ日時・取込ファイル名(2行目が最新。見出しはユーザーが用意、列は見出しの文字で探す) |
| 利用記録(非表示) | 起動・ダウンロード(画面には記録したことを出さない) |

## セットアップ(初回だけ)
1. スプレッドシート「鳥取工場生産状況周知」を開き、「拡張機能 → Apps Script」。
2. `gas/Code.gs` の全文を貼って保存。左の「サービス」の＋から **Drive API(v3)** を追加。
3. `setupSheets` を実行(初回は権限の承認が出る)。シートと見出しができる(以前の版の自動更新の予約も消える)。
4. 「情報」シートの `索引スプレッドシート` の値に、「Excelマスタ一覧」のURLを貼る。
5. (`refreshNow` は不要。アプリでPDFを読み込むと、その工事のファイルを読む)
6. 「デプロイ → 新しいデプロイ → 種類: ウェブアプリ」。次のユーザーとして実行=自分、アクセスできるユーザー=全員。
   GASを使うアプリは mst アカウントで作成・デプロイする(`docs/know-how.md`)。そのアカウントが案件マスターを読めること。
7. 表示されたウェブアプリのURLを、`app.js` の `GAS_URL` に入れる(Claudeに伝えれば反映する)。

GASを直したら `CODE_VERSION` を上げ、「デプロイを管理 → 編集 → 新バージョン」。反映は `?action=ping` の版で確認する。
