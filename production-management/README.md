# 生産管理ダッシュボード：GAS × 静的ページ(Vercel) 分離構成

鉄骨加工の日次生産実績を、案件（工事）別マスターExcel（Googleドライブ）から自動集計し、
拠点別の生産量グラフと、拠点×工事×部位の日別工程表として可視化するダッシュボードです。
構成は**静的ページ(Vercelで配信) + Google Apps ScriptでJSON API**です。
本番: https://masamiz-production-management.vercel.app/ (Vercelプロジェクト production-management、Root Directory=production-management)

## 構成

```
production-management/
  index.html     … フロントエンドのHTML(画面構造のみ。初回のgetDataを先に開始する)
  style.css      … スタイル
  app.js         … 画面ロジック + グラフ描画(Chart.jsをCDNから読み込み) + 工程表描画
                   + GAS APIとの通信処理(fetchでGET、キャッシュ済みデータの取得と手動更新)
  manual.html    … 説明書(ヘッダーの「説明書」ボタンで別タブ表示)
  to-launcher.js … 「← アプリ一覧へ」ボタン(正本 docs/to-launcher/to-launcher.js のコピー)
  vercel.json    … {"git":{"deploymentEnabled":false}}(push・マージで自動デプロイしない)
  gas/Code.gs    … GAS側に貼り付けるバックエンドコード(集計処理専用のJSON API)
```

## データの流れ

1. 各拠点・案件ごとの「マスターExcel」（部材1行＝1レコード。柱・大梁・小梁など部位、加工先
   （本社/夢前/鳥取）、加工日、本数、重量などを保持）が、担当者によって随時Googleドライブ上で
   更新されます。**このアプリはこれらのExcelファイルを常に読み取り専用で開き、一切書き込みません。**
2. 「Excelマスタ一覧」スプレッドシート（索引シート）に、各マスターExcelの工事番号・ファイル名・
   URLが一覧化されています。拠点はマスターの「加工先」列(本社/夢前/鳥取)で決まり、同じ工事を
   複数拠点で加工している場合は、工程表の拠点ごとのブロックにそれぞれの内訳として表示します(合算しない)。
3. GASは、この索引シートに従って各マスター(Excelまたは既にGoogleスプレッドシート)を読み込みます。
   Excelファイルの場合はGASが`.xlsx`を直接高速処理できないため、更新（自動または手動）のタイミング
   でのみ、索引シートと同じフォルダ内に**作業用のGoogleスプレッドシートを作成（既存があれば内容
   だけ上書き）**して変換し、そこから集計します（元のExcelファイル本体には一切触れません）。
   既にGoogleスプレッドシート形式のマスターはこの変換をスキップし、直接読み込みます。
4. 集計結果は同じフォルダ内の `_cache_dashboard.json` に保存され、通常の画面表示はこの
   キャッシュを読むだけなので高速です（変換・集計という重い処理は、更新ボタンを押した時、または
   毎日早朝の自動トリガー時のみ発生します）。

## 1. 索引スプレッドシートの構成(1枚目のシートに以下の列。手動で用意済み)

| 列 | 内容 |
|---|---|
| A | ドライブ(参考情報。アプリのロジックでは使用しない) |
| B | マスタNo(先頭が`S`ならE列URLの先はGoogleスプレッドシート、それ以外(数字のみ・`E`始まりなど)はExcelファイルとして扱う) |
| C | 工事番号(空欄、または`00-00`の行はテンプレートファイルとして無視する) |
| D | ファイル名 |
| E | URL(案件マスターExcelファイルへの共有リンク) |
| G | 工事番号(工事番号→工事名の対応表) |
| H | 工事名 |
| I | Date(会社カレンダー) |
| J | Holiday(「出勤」または「休日」) |
| K | 拠点名(本社/夢前/鳥取) |
| L | 目標日産量デフォルト(トン) |

各マスターExcel側は、部材1行につき「部位」「加工先」「本数」「重量」「加工」（加工日）の列を
持っている前提です（列の並び順はファイルによって多少ずれても、見出し文字列で自動判定します）。

## 2. GAS側(バックエンドAPI)のセットアップ

このアプリのGASは、**索引スプレッドシート（「Excelマスタ一覧」）にコンテナバインド**して使います
(`SpreadsheetApp.getActiveSpreadsheet()`で自動的に自分自身を参照するため、`SPREADSHEET_ID`の
設定は不要です)。

1. 「Excelマスタ一覧」スプレッドシートを開き、「拡張機能→Apps Script」を開きます。
2. `gas/Code.gs` の内容をまるごとコピー&ペーストします。
3. 左側の「サービス」（＋）から **「Drive API」** を追加します(xlsx→Googleスプレッドシート
   変換に必要な高度なサービスです)。
4. 保存後、エディタ上部の関数選択で **`checkSetup`** を選び、▶実行ボタンを押すと、索引
   スプレッドシートの構成（案件マスターファイル件数・工事名リスト件数・カレンダー日数・目標値・
   作業用ファイルの保存先フォルダ）がログに出ます(初回はアクセス許可の承認が必要です)。
5. 関数選択で **`createDailyTrigger`** を選び、▶実行すると、毎日5:00頃に自動更新するトリガーが
   設定されます(初回のみでOKです)。
6. 右上の **「デプロイ」→「新しいデプロイ」** を選択します。
7. 歯車アイコンから種類を **「ウェブアプリ」** に設定し、以下を指定します。
   - **説明**: 任意(例: `api-v1`)
   - **次のユーザーとして実行**: 「自分」
   - **アクセスできるユーザー**: **「全員」**(フロントエンドから匿名でアクセスするため必須)
8. 「デプロイ」をクリックし、表示される **新しいウェブアプリのURL**(`https://script.google.com/macros/s/xxxxx/exec`)をコピーします。
9. **このURLをClaudeとのチャットに貼り付けてください。** `app.js` の `GAS_API_URL` と、`index.html` の
   初回取得用のURL(同じ値)に反映してGitHubにpushします。
10. コードを修正した場合は、この新規デプロイを編集し「新バージョン」として更新すればURLは
    変わりません。

### 注意点

- 元のマスターExcelファイル、索引スプレッドシートには一切書き込みません(読み取り専用)。
- 変換用の作業スプレッドシート・集計キャッシュ(`_cache_dashboard.json`)・案件ごとの読み込み結果
  キャッシュ(`_records_cache.json`。ファイルの更新日時が前回と変わっていない案件はここに保存
  済みの結果を使い回し、変換・再読み込み自体をスキップすることで更新を高速化する)は、索引
  スプレッドシートと同じGoogleドライブフォルダ内に作成され、更新のたびに同じファイルへ上書き
  されます(フォルダ内が増え続けることはありません)。
- レスポンスは常にHTTP 200で返り、成否は返却JSONの `status` フィールド(`success`/`error`)で
  判定します。

## 3. フロントエンド(Vercel)の公開

1. `production-management/app.js` の先頭にある `GAS_API_URL` と、`index.html` の初回取得用のURLを、
   手順2で取得したウェブアプリのURLに書き換えます(2か所とも同じ値)。
2. 変更をリポジトリにコミット・プッシュし、mainブランチに反映します。
3. Vercelとの Git連携はしない(`vercel.json` で自動デプロイも停止)。本番への反映は、ユーザーが
   「デプロイして」と指示したときだけ `create_deployment` で行う(運用はリポジトリの `CLAUDE.md` と
   `docs/vercel-status.md`)。GitHub Pages は使わない。
4. 開発中の画面確認は raw.githack(`https://raw.githack.com/aism24/-/<コミットSHA>/production-management/index.html`)。
   `index.html` の `app.js?v=` を変更のたびに更新する。

## 4. 動作確認チェックリスト

- [ ] ページを開くと、拠点別の生産量グラフ(日次バー＋累積実績・目標ラインの折れ線)が表示される
- [ ] 拠点ボタンで「全て」または1拠点だけ(本社/夢前/鳥取)に切り替えられる
- [ ] 期間セレクトで「前月21日〜当月20日」の締め期間を過去分も含めて切り替えられる
- [ ] 拠点カードの平均生産重量は「生産重量÷営業日数」。進行中の期間は昨日までの分で計算する(今日の
      生産・今日の営業日はどちらも含めない)。経過した営業日が0日(締め期間の初日など)は「−」で赤にしない
- [ ] 目標日産量の入力欄を変更すると、その場でグラフの目標ラインだけ更新される(リロードすると
      索引シートのデフォルト値に戻る)
- [ ] 工程表に、拠点×工事(工事番号+工事名)×部位(柱/大梁/小梁/他/生産重量)の日別マトリックスが
      表示される。休日の列が色分けされる
- [ ] 同じ工事番号が複数拠点にある場合、それぞれの拠点ブロックに同じ工事名で表示される(合算では
      なく拠点ごとの内訳として表示)
- [ ] 「現時点のデータを取得」ボタンを押すと、Excelから再集計され、完了後に画面が更新される(数十秒かかる
      場合があります)
- [ ] 一部のマスターExcelが読み込めない場合でも、画面下部に警告が表示されつつ他のデータは
      問題なく表示される
- [ ] スマホ・iPadで開いても、表が横スクロールでき、レイアウトが崩れない

## トラブルシューティング

- **データが表示されない/エラーになる**: `GAS_API_URL` が正しいか、GASデプロイの
  「アクセスできるユーザー」が「全員」になっているか確認してください。
- **「現時点のデータを取得」が失敗する、または特定案件が工程表に出ない**: Apps Scriptエディタで
  「サービス」に「Drive API」が追加されているか、索引シートのファイルURLが正しいか、GASを
  実行するGoogleアカウントがそのExcelファイル・フォルダを閲覧できるか確認してください。
- **列が見つからないエラー**: マスターExcel側に「部位」「加工先」「本数」「重量」「加工」の
  見出しがすべて存在するか確認してください(列の順番は自由です)。
