# GAS × GitHub Pages 分離構成サンプル

Google Apps Script（GAS）で作ったWebアプリを、**フロントエンド（GitHub Pages）** と **バックエンド（GAS API）** に分離する構成のサンプルです。

GASのWebアプリをそのまま公開すると、`script.google.com` ドメインになり、初回アクセス時に警告バナーが表示されることがあります。この構成ではUIをGitHub Pagesで配信し、GASはデータ処理専用のAPIとして呼び出すことで、これを回避します。

## 構成

```
index.html   … フロントエンドのHTML
style.css    … スタイル（レスポンシブ対応）
app.js       … GAS APIとの通信処理（fetchでGET/POST）
gas/Code.gs  … GAS側に貼り付けるバックエンドコード
```

サンプルアプリはシンプルな「メッセージボード」です。フォームから投稿（POST）し、一覧を取得（GET）します。実際のアプリに合わせて `app.js` の通信処理と `gas/Code.gs` のロジックを書き換えて使ってください。

---

## 1. GAS側（バックエンドAPI）のセットアップ

1. [Google Apps Script](https://script.google.com/) で新規プロジェクトを作成します。
   - スプレッドシートをデータストアとして使う場合は、スプレッドシートを開いて「拡張機能」→「Apps Script」から作成すると、コンテナバインドのスクリプトになり、`SPREADSHEET_ID` を空のままで動作します。
2. `gas/Code.gs` の内容をエディタに貼り付けます。
3. 保存後、右上の **「デプロイ」→「新しいデプロイ」** を選択します。
4. 歯車アイコンから種類を **「ウェブアプリ」** に設定し、以下を指定します。
   - **説明**: 任意（例: `api-v1`）
   - **次のユーザーとして実行**: 「自分」
   - **アクセスできるユーザー**: **「全員」**（この設定が重要です。フロントエンドから匿名でアクセスするため「全員」にする必要があります）
5. 「デプロイ」をクリックし、表示される **ウェブアプリのURL**（`https://script.google.com/macros/s/xxxxx/exec` の形式）をコピーします。
6. 初回デプロイ時にGoogleアカウントの承認画面が出るので、権限を許可してください。
7. コードを修正した場合は、既存のデプロイを更新するか、新しいデプロイを作成してURLを再取得してください（「デプロイを管理」→ 対象デプロイの編集アイコン→ バージョンを「新バージョン」にして更新すると、URLを変えずに反映できます）。

### 注意点

- GASのウェブアプリはCORSのプリフライト（OPTIONSリクエスト）に対応していないため、`app.js` からのPOSTは `Content-Type: text/plain` で送信し、GAS側で `JSON.parse(e.postData.contents)` として読み取っています。`application/json` を指定するとプリフライトが発生し失敗するので変更しないでください。
- レスポンスは常にHTTP 200で返り、成否は返却JSONの `status` フィールド（`success` / `error`）で判定します。

---

## 2. フロントエンド（GitHub Pages）のセットアップ

1. `app.js` の先頭にある `GAS_API_URL` を、手順1で取得したウェブアプリのURLに書き換えます。

   ```js
   const GAS_API_URL = "https://script.google.com/macros/s/xxxxx/exec";
   ```

2. 変更をリポジトリにコミット・プッシュします。
3. GitHubリポジトリの **Settings → Pages** を開きます。
4. **Source** で以下を設定します。
   - `Deploy from a branch`
   - ブランチ: 公開したいブランチ（例: `main`）、フォルダ: `/ (root)`
5. 保存すると数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。
6. 公開URLは Pages設定画面の上部に表示されます。

---

## 3. 動作確認

1. GitHub PagesのURLにブラウザでアクセスします。
2. ページを開いた直後に「読み込み中...」が表示され、既存の投稿一覧（GETリクエストの結果）が表示されることを確認します。
3. 「お名前」「メッセージ」を入力して「送信する」を押し、以下を確認します。
   - 送信中はボタンがローディング表示になり、二重送信できないこと
   - 送信成功後、一覧に新しい投稿が反映されること
4. GAS APIのURLを一時的に無効な値に変えるなどしてエラーを発生させ、赤色のエラーバナーが表示されることを確認します（正しいURLに戻すのを忘れないでください）。
5. ブラウザの開発者ツールのNetworkタブで、`?action=list` へのGETと、本文JSONを送るPOSTがそれぞれ正常なレスポンス（`status: "success"`）を返していることを確認します。

---

## カスタマイズのヒント

- 別のデータ（例: 問い合わせフォーム、アンケート結果など）を扱う場合は、`gas/Code.gs` の `listItems_` / `addItem_` とスプレッドシートの列構成、`app.js` の `renderList` / `submitPost` を合わせて変更してください。
- `action` パラメータ（GET）や `action` フィールド（POST）を増やすことで、複数の処理を1つのGASデプロイで提供できます。
