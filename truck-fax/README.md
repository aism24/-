# 車番連絡 取込(truck-fax)

運送会社から届く「車番連絡FAX(配車連絡表)」のPDFを取り込み、内容を自動で読み取って
スプレッドシート「車番連絡自動化」に記録するアプリです。**画面はすべてテーブル表示**です。

- 流れ: ①PDFを取り込む → ②Geminiが内容を抽出 → ③行先から工事番号・現場名を選ぶ(過去と同じものが初期値)
  → ④車両・運転手のマスタと照合して、食い違いは画面で確認・編集 → ⑤取込一覧に記録
- 現在のFAXは、スキャンしたPDF(文字情報なし)。将来メールで受け取るPDF(文字情報あり)も、同じ流れで読み取れる。
- 構成: 静的な画面(`index.html`・`app.js`・`logic.js`・`style.css`)+ GAS(`gas/Code.gs`。スプレッドシートにコンテナバインド)。
  Vercelの自動デプロイは `vercel.json` で停止(本番反映は「デプロイして」の指示時のみ)。

## スプレッドシートの構成

| シート | 内容 |
|---|---|
| 取込一覧 | 記録先。**見出し名で読み書きする**ので、列の追加・並べ替えに強い。見出し: タイムスタンプ / ファイル名 / 工事番号 / 現場名 / 手配業者 / 積日 / 卸日 / 行先 / 着時間 / 運送業者 / 車種 / 車番 / 氏名 / 携帯番号 / **追加変更** / **備考**。手配業者には、FAXの送り主を「ナミツー」「大上」などの短い名前で記録する(下の「手配業者の候補」)。**PDFで取り込んだ行は、取込一覧から消さない** |
| 車両情報 | 手配業者 / 運送業者 / 車種 / 車番 |
| 運転手携帯番号 | 運送業者 / 氏名 / 携帯番号 |
| 情報 | A列=項目名、B列=値。`Geminiモデル名`・`タイムゾーン`・`APIKEY`。工事番号と工事名のリスト(見出し「工事番号」「工事名」の列)も、ここから読む |
| マスタ変更履歴 | マスタの追加・更新・削除の記録(`setupSheets`で自動作成) |

**Geminiのモデル名とAPIキーは、「情報」シートのセルから読みます**(コード修正・再デプロイ不要。`CLAUDE.md` の例外ルール参照)。
モデルを変えるときは「Geminiモデル名」のセルを書き換えるだけです。セルが空のときは、別モデルに切り替えず、エラーにします。
APIキーはGAS内でだけ使い、画面・GitHubには出ません。

## セットアップ(1回だけ)

1. スプレッドシート「車番連絡自動化」を開き、「拡張機能 → Apps Script」を開く。
2. `gas/Code.gs` の全文を貼り付けて保存する(GitHubの通常のファイル表示ページの「Copy raw contents」でコピーできる)。
3. 関数 `setupSheets` を選んで1回実行する(初回は承認が必要。不足しているシートと見出し、情報シートの項目だけを追加し、既存の内容は消さない)。
4. 「情報」シートの `APIKEY` に、Gemini APIキーを入れる(`Geminiモデル名`は `gemini-3.5-flash-lite`)。
5. 「デプロイ → 新しいデプロイ → ウェブアプリ」。実行ユーザー=自分、アクセスできるユーザー=全員。
6. 表示された `/exec` のURLを `app.js` の `GAS_API_URL` に設定する(Claudeに伝えれば設定してpushする)。
7. 以降、`Code.gs` を直したときは、デプロイを編集して「新バージョン」にする(URLは変わらない)。

## 変更・追加・取消のFAX(一度受領した連絡の続報)

読み取りの結果、FAXの区分(新規・変更・追加・取消)を判定する(「再」「訂正」「変更」の印や文言、取消線の有無)。画面で選び直すこともできる。
新規以外は、通常の取込ではなく、**「現在の記録」と「今回」を並べた表**を出す。違う項目は色が付く。

**PDFで取り込んだ行は、取込一覧に必ず残す。行の削除・内容の上書きはしない。** 列「追加変更」の印で区別する。

| 区分 | 取込一覧の動き |
|---|---|
| 新規 | 行を追加する(追加変更は空欄) |
| 変更 | 元の記録(手配業者・積日・行先と、取消線の車番で探す)の「追加変更」を**変更前**にし、今回の内容を**変更後**の新しい行として追加する。空欄の積日・行先などは元の記録から引き継ぐ |
| 取消(中止) | 元の記録の「追加変更」を**中止**にする(行は残す)。元の記録が無いときは、FAXの内容を「中止」の行として追加できる |
| 追加 | 新しい1台を行として追加する(追加変更は空欄。同じ手配の工事番号を引き継ぐ) |

- **車両台数**は、「追加変更」が `中止`・`変更前` **以外**(空欄・`変更後`)の行を数える。
- 元の記録の候補は、中止・変更前にした行を除く(その行を、もう一度変更・中止にはしない)。
- 元の記録が1つに決まらないときは、自動で選ばず、画面で選ぶ。見つからないときは、変更後の行として追加するのが既定。
- 備考: 表の「備考(入力)」に、アプリでテキストを入力する(通常の取込も、変更・追加の行も)。中止にするときは、その行の備考に書ける。
- 「追加変更」「備考」の列が取込一覧に無くても動く(その列には書かない)。ただし、変更前・中止の印を付けるには、列「追加変更」が必要。
- 印を付けた操作は、シート「変更履歴」にも残る(自動作成)。
- 反映の直前に、取込一覧が変わっていないか確認する(新旧を同時に取り込んだ場合など、変わっていたら照合し直して、もう一度確認する。行の内容が他の操作で変わっていたら、何も変えずに止める)。

## 手配業者の候補

FAXの送り主は、候補の名前(既定: `ナミツー`・`大上`)に当てはまるものを、PDFの発信元から判断して、その名前だけで記録する。
候補は、「情報」シートに、見出し「手配業者」の列を作り、その下に1行1社で書く(空行まで読む)。無ければ既定を使う。
候補に当てはまらない送り主は、書かれたとおりに記録し、画面に注意を出す。
既存の記録の表記(「(有)大上運送 明石事業所」など)は、Apps Scriptのエディタで関数 `normalizeSenders` を1回実行すると、候補の名前にそろう(取込一覧と車両情報。当てはまらないものは変えない)。

## 画面の使い方

- **① 取込**: PDF(複数可)をドロップ。読み取り結果が表で出る。間違いは表の中で直せる。「原本を見る」で元のFAXを横に開いて照合できる。
  - **工事番号**: 行先から、取込一覧の過去の記録で最後に選んだ工事を初期値にする。違うときは、情報シートの一覧から選び直す(現場名が連動)。
  - **照合・確認事項**(表): マスタとの食い違い・重複・新規を一覧する。要確認の項目は、対応を選ばないと記録できない。
- **取込一覧 / 車両情報 / 運転手**: 表で表示。マスタは編集・削除・追加ができ、変更前の値つきで保存する(他の人が先に変えていたら拒否)。重複は赤で表示。

## 照合ルール(`logic.js`)

表記ゆれ(全角半角・空白・ハイフン・㈱/(株)・株式会社)を吸収して比べる。記録する値は、FAXの表記のまま。

| 判定 | 対応の選択肢 |
|---|---|
| 車番が車両情報に無い / 運転手がマスタに無い | 新規登録する(既定)/ 登録しない |
| 同じ車番で、手配業者・運送業者・車種が違う | マスタを更新 / 取込をマスタに合わせる / 今回だけ |
| 同じ氏名・運送業者で、携帯番号が違う | マスタを更新 / 取込をマスタに合わせる / 今回だけ |
| 同じ携帯番号で、氏名・運送業者が違う(改名・読み間違い) | マスタを更新 / 取込をマスタに合わせる / 別人として登録 / 今回だけ |
| 同じ氏名が別の運送業者にある | 別人として登録 / 今回だけ |
| 積日+車番が取込一覧・同じFAX内にある | 重複を承知で記録 / 記録しない |
| マスタ内の重複(車番・氏名+運送業者・携帯番号) | 確認した(マスタ画面で整理) |
| 車番・積日・卸日が空 | 表を直す(要修正) |

## 注意

- FAXの画像・氏名・電話番号は個人情報のため、リポジトリには入れない(公開リポジトリ)。
- Geminiの読み取りは、書式が違うFAX(業者ごと)でも同じ指示で行う。読み間違いは、確認の表で直す。初めての書式は、原本と見比べて確認する。
