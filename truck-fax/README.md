# 車番連絡 取込(truck-fax)

運送会社から届く「車番連絡FAX(配車連絡表)」のPDFを取り込み、内容を自動で読み取って
スプレッドシート「車番連絡自動化」に記録するアプリです。**画面はすべてテーブル表示**です。

- 流れ: ①PDFを取り込む → ②Geminiが内容を抽出 → ③行先から工事番号・現場名を選ぶ(過去と同じものが初期値)
  → ④車両・運転手情報と照合して、食い違いは画面で確認・編集 → ⑤取込一覧に記録
- 現在のFAXは、スキャンしたPDF(文字情報なし)。将来メールで受け取るPDF(文字情報あり)も、同じ流れで読み取れる。
- 構成: 静的な画面(`index.html`・`app.js`・`logic.js`・`style.css`)+ GAS(`gas/Code.gs`。スプレッドシートにコンテナバインド)。
  Vercelの自動デプロイは `vercel.json` で停止(本番反映は「デプロイして」の指示時のみ)。

## スプレッドシートの構成

| シート | 内容 |
|---|---|
| 取込一覧 | 記録先。**見出し名で読み書きする**ので、列の追加・並べ替えに強い。見出し: タイムスタンプ / ファイル名 / 工事番号 / 現場名 / 手配業者 / 積日 / 卸日 / 行先 / 着時間 / 運送業者 / 車種 / 車番 / 氏名 / 携帯番号 / **追加変更** / **備考**。手配業者には、FAXの送り主を「ナミツー」「大上」などの短い名前で記録する(下の「手配業者の候補」)。**PDFで取り込んだ行は、取込一覧から消さない(2026-10-21から、画面で行の内容を直すことはできる。削除はできない)** |
| 記録 | **利用記録(利用者には分からないよう裏で書く。画面に表示しない。2026-10-26、ユーザー指示)**。A=アプリ起動日時 / B=ダウンロード日時 / C=ファイル名。2行目が最新(古いものほど下)。起動のたびに2行目へ挿入(B:Cは空欄)。ダウンロード(取込一覧の全件・締め月・積日指定、車両・運転手情報のExcel)は、その起動の行のB:Cが空ならそこへ、すでに入っていれば新しい行を2行目に挿入(Aは同じ起動日時)。GAS `logStart` / `logDownload`(GET)、画面は `app.js` の `logStart`・`downloadXlsx`。GAS 20261026a |
| 車両運転手情報 | 手配業者 / 運送業者 / 車種 / 車番 / 氏名 / 携帯番号 / 備考(2026-10-22に、車両情報と運転手携帯番号を統合した。1行=車と運転手の1組) |
| 情報 | A列=項目名、B列=値。`Geminiモデル名`・`タイムゾーン`・`APIKEY`。工事番号と工事名のリスト(見出し「工事番号」「工事名」の列)も、ここから読む |

**Geminiのモデル名とAPIキーは、「情報」シートのセルから読みます**(コード修正・再デプロイ不要。`CLAUDE.md` の例外ルール参照)。
モデルを変えるときは「Geminiモデル名」のセルを書き換えるだけです。セルが空のときは、別モデルに切り替えず、エラーにします。
APIキーはGAS内でだけ使い、画面・GitHubには出ません。

## セットアップ(1回だけ)

1. スプレッドシート「車番連絡自動化」を開き、「拡張機能 → Apps Script」を開く。
2. `gas/Code.gs` の全文を貼り付けて保存する(GitHubの通常のファイル表示ページの「Copy raw contents」でコピーできる)。
3. 関数 `setupSheets` を選んで1回実行する(初回は承認が必要。不足しているシートと見出し、情報シートの項目だけを追加し、既存の内容は消さない)。
4. 「情報」シートの `APIKEY` に、Gemini APIキーを入れる(`Geminiモデル名`は `gemini-3.5-flash-lite`)。
5. 「デプロイ → 新しいデプロイ → ウェブアプリ」。実行ユーザー=自分、アクセスできるユーザー=全員。
6. 表示された `/exec` のURLを `app.js` の `GAS_API_URL` に設定する(Claudeに伝えれば設定してpushする)。
7. 以降、`Code.gs` を直したときは、デプロイを編集して「新バージョン」にする(URLは変わらない)。

## 変更・追加・取消のFAX(一度受領した連絡の続報)

読み取りの結果、FAXの区分(新規・変更・追加・取消)を判定する(「再」「訂正」「変更」の印や文言、取消線の有無)。画面で選び直すこともできる。
新規以外は、通常の取込ではなく、**「現在の記録」と「今回」を並べた表**を出す。違う項目は色が付く。

**PDFで取り込んだ行は、取込一覧に必ず残す。行の削除・内容の上書きはしない。** 列「追加変更」の印で区別する。

| 区分 | 取込一覧の動き |
|---|---|
| 新規 | 行を追加する(追加変更は空欄) |
| 変更 | 元の記録(手配業者・積日・行先と、取消線の車番で探す)の「追加変更」を**変更前**にし、今回の内容を**変更後**の新しい行として追加する。空欄の積日・行先などは元の記録から引き継ぐ |
| 取消(中止) | 元の記録の「追加変更」を**中止**にする(行は残す)。元の記録が無いときは、FAXの内容を「中止」の行として追加できる |
| 追加 | 新しい1台を行として追加する(追加変更は空欄。同じ手配の工事番号を引き継ぐ) |

- **車両台数**は、「追加変更」が `中止`・`変更前` **以外**(空欄・`変更後`)の行を数える。
- 元の記録の候補は、中止・変更前にした行を除く(その行を、もう一度変更・中止にはしない)。
- **「再」の印が無い変更の再送(2026-10-23、ユーザー指示)**: 「新規」と読めたFAXでも、①一部の行が取込一覧の記録(中止・変更前を除く)と全く同じ、または ②備考・特記・連絡文に「変更」「訂正」「差替」があり、同じ手配業者・積日の記録がある ときは「変更」として扱い、理由を画面の注意に出す(「このFAXは」で選び直せる)。例: 1枚目(杉田・牛尾)→2枚目(杉田・甲、特記「車両変更です」)は、杉田の行=変更なし、甲の行=牛尾の行を変更前にして変更後を追加。全部の行が同じときは、従来どおり取込をやめる。`logic.js` の `guessKind`。
- **積日・卸日の違う別の便を、元の記録にしない(2026-10-23、ユーザー指示)**: 同じ運転手が連続で運ぶことがある(例: 立田さん 9/25積→9/28積)。元の記録の点数は、積日が両方書かれていて違えば−4、卸日が違えば−2(合計3点未満は選ばない)。また、Geminiは「再」の印のあるFAXで、取消線の無い行を取消線ありと読むことがある(実測。大上 9/28積のFAXで立田さんの行)。取消線と読まれた行でも、同じ車番の記録があり、どれも積日が違う(別の便)ときは、取消線なしの行として扱う(`struckHasOrigin`)。同じ車番の記録が無いときは、読み取りのまま。
- **元のFAXが無い「変更」は「新規」(2026-10-23、ユーザー指示)**: 「再」「変更」の文字や印があっても、同じ手配業者・同じ積日の記録(元のFAX)が取込一覧に1つも無いときは、全く別の車番連絡として「新規」の取込にし(取消線も外す)、理由を注意に出す(`changeOrNew`。取消線の行の積日も見る)。例: 9/25積のFAX(立田・藤本)のあとの、「再」の印のある 9/28積のFAX(立田・當房)は、2行とも普通の行(追加変更は空欄)として記録する。
- 元の記録が1つに決まらないときは、自動で選ばず、画面で選ぶ。見つからないときは、変更後の行として追加するのが既定。
- **変更のFAXの自動選択(2026-10-23、ユーザー指示)**: FAXの行と元の記録を、点数の合計が最大になるように1対1で組み合わせ、選べた行は対応も「変更前→変更後」を既定にする。点数=取消線の車番6・行先(両方記入)4・今回の車番3・運転手2・積日1(3点未満は選ばない)。車や運転手が入れ替わっても行先(どの便か)は変わらないことが多いため、行先を重く見る。例: 伏見区=4400荒木→6600荒木、堺市=6600荒木→9001土肥 は、伏見区の行・堺市の行がそれぞれ元の記録になる。工事番号は、元の記録の値を引き継ぐ(人が選んだ工事番号は変えない)。
- **取込一覧で変更前の下に変更後を並べ、変わった項目に矢印(2026-10-27、ユーザー指示)**: 表(とExcelの並び)で、「変更後」の行を対応する「変更前」の行の真下に置く(変更前が上、変更後が下)。変更前の行の変わった項目には紫の太い矢印(SVGの図。文字「⤵」はフォントによって太字にならないため)、変更後の行の同じ項目は赤太字・薄い赤の背景にする(Excelには矢印・色は付けない)。シートに組み合わせの印は無いため、画面が同じ手配業者・同じ積日の中で、行先4・車番3・氏名2・車種1・卸日1の点数が最大になるよう1対1で決める(3点未満は組み合わせない=並べ替えも矢印もしない)。比べる項目: 手配業者・積日・卸日・行先・着時間・運送業者・車種・車番・氏名・携帯番号(備考・現場名は比べない)。`logic.js` の `pairBeforeAfter` と `sortImportRows`。
- **原本を閉じたとき(2026-10-27、ユーザー指示)**: 取込一覧で行を押して原本を開き、「すべての行に戻す」「画像を閉じる」で戻ると、開いていた行が表の一番上(見出しの下)に来るようにスクロールする(以前は一番古い日付が一番上に戻り、どこを開いたか分かりにくかった)。下の方の行は、下に余白を足して一番上まで動かす。
- **変更なし(2026-10-23、ユーザー指示)**: 変更のFAXの行が、取込一覧の記録(中止・変更前を除く)と、書かれている項目すべて一致するときは、対応を「変更なし(記録しない)」にして記録しない(その記録は、他の行の元の記録にしない)。対応の選択肢「変更なし(記録しない)」は手でも選べる(旧名「反映しない」)。記録しない行には確認を出さない。
- 備考: 表の「備考(入力)」に、アプリでテキストを入力する(通常の取込も、変更・追加の行も)。中止にするときは、その行の備考に書ける。
  **FAXにその他の文字があれば、読み取って備考の初期値に入れる**(記録前に直せる): ただし「入場予定時間:夢前工場」のように、入場予定時間の欄の下の積地(時刻を含まない)と「積地:…」は特記事項ではないので入れない(2026-10-23、ユーザー指示。`logic.js` の `cleanNote`。時刻を含む「入場予定時間:8:00」は残す)。 **「現着時間(荷卸し時間):6:30待機」も入れない**(着時間の列と同じ内容のため。着時間が空なら、その時刻を着時間に入れる。2026-10-23、ユーザー指示。GASの指示文でも、現着時間・入場予定時間・積地を備考に入れないよう指示(20261023b))。**備考は文字として書く**(「10:30」がスプレッドシートで時刻になり「1899/12/30 10:30:00」と表示されていた。既に時刻になったセルは、読むときに「10:30」と返す。GAS 20261023b)。 行の「備考」「特記」「荷種」「入場予定時間」などの欄の文字(「備考」以外の欄は「特記:午前着希望」のように欄名つき)と、FAXの連絡文(「変更すみません」など。印字の定型のあいさつは入れない)。両方あるときは「 / 」でつなぐ。
- 「追加変更」「備考」の列が取込一覧に無くても動く(その列には書かない)。ただし、変更前・中止の印を付けるには、列「追加変更」が必要。
- 履歴のシートは作らない。経緯は、取込一覧の「追加変更」(変更前・変更後・中止)と、各行のファイル名・タイムスタンプで分かる。
- 反映の直前に、取込一覧が変わっていないか確認する(新旧を同時に取り込んだ場合など、変わっていたら照合し直して、もう一度確認する。行の内容が他の操作で変わっていたら、何も変えずに止める)。

## 記録するときの表記

- **複数の車種に乗る運転手の備考(2026-10-22、ユーザー指示。GAS 20261022g)**: 同じ運転手の行が、車種違いで2つ以上あるとき、**どの行の備考にも「10t/高TR」の形で車種を書く**(並びは 4t→10t→15t→TR→その他。備考の他の文字、例:「大上/ナミツー」は残し、後ろに置く。車種が増えたら並びを置き換える)。記録のあと・車両・運転手情報の表の保存のあと・`init` で、GAS(`syncTypeNotes_`)が自動で書く(変わる行だけ)。画面の表は、シートの値をそのまま出す。
- **運送業者**: かっこ書きは取り除いて記録する(例: `トランスポート千税(チカラ)`→`トランスポート千税`。全角も。2026-10-22、ユーザー指示)。`(株)`・`(有)`・`(合)`・`(同)`などの会社の種類は残す。FAXの読み取り結果(`logic.js` の `fmtCarrier`)に適用する。表で手入力した値は変えない。
- **車種**: 数字のあとの大文字「T」は小文字の「t」にそろえ、空白は除く(例: `10T平`→`10t平`、`4 T平`→`4t平`、全角の「Ｔ」も)。**「TR」「高TR」のように数字が前に付かないTは、そのまま**(以前は「高TR」が「高tR」になってしまっていた)。取込一覧と車両・運転手情報に、そろえて記録する。
- 現場名(情報シートの工事名)は、選んだとおりに記録する(`AT-OSK2プロジェクト` のような英字を変えない)。
- 手配業者・運送業者は、書き方の違い(`大上運送`/`大上運送 明石事業所`/`(有)大上運送`)を同じ会社とみなして照合する。2度目の運行など、車と運転手の組み合わせが車両・運転手情報に既にあるときは、追記しない。組み合わせが無いときは、同じ車に別の運転手・同じ運転手が別の車でも、別の行として自動で追加する(2026-10-22。車が登録済みでも、新しい運転手は確認なしで登録する。以前は、車番が登録済みで運転手が未登録のとき、氏名・携帯番号の読み間違いの疑いとして、選ぶまで記録できなかった)。

## 運送業者の書き方・食い違いの見せ方(2026-10-23、ユーザー指示)

- 読み取った運送業者が、車両・運転手情報に登録済みの運送業者と、会社の種類・空白・**小さいカナ/大きいカナ**の違いだけなら、登録済みの書き方にそろえる(例: 「近畿ロジステイクス」→「近畿ロジスティクス」。`logic.js` の `canonCarrier`・`companyKey`)。そろえるので、確認は出ず、車両・運転手情報に別の行も増えない。
- 「確認が必要な項目」には、食い違う部分だけを「立田[祐]史 か 立田[裕]史 か?」の形で色付きで出す(左=登録済み、右=今回。運送業者・氏名・携帯番号。`diffPart`)。

## 手配業者の候補

FAXの送り主は、候補の名前(既定: `ナミツー`・`大上`)に当てはまるものを、PDFの発信元から判断して、その名前だけで記録する。
候補は、「情報」シートに、見出し「手配業者」の列を作り、その下に1行1社で書く(空行まで読む)。無ければ既定を使う。
候補に当てはまらない送り主は、書かれたとおりに記録し、画面に注意を出す。

## 画面の使い方

タブは、画面上部のアプリ名の行(固定表示)の左端にボタンとして並べる。**左のボタンの左端と、右の会社ロゴ・会社名の右端は、取込枠(白いカード。幅980px以内・中央)の左右の端にそろえる**(2026-10-23、ユーザー指示。取込一覧・車両・運転手情報の画面でも同じ位置)。ボタンの左右の余白は8px(間は4px)にして、その幅の中で3つのボタンが1行に収まるようにする(14pxでは、車両・運転手情報モードのとき2行に折り返していた)。画面全体の背景は濃いグレー、表は白地(項目の行は薄いグレー)。Excelは、外部ライブラリなしの `xlsx.js` で作る。

- **PDF取込**: PDFを**画面のどこへでも**ドロップ(1回に1ファイル。複数入れたときは最初の1つ)。取込枠のクリックでも選べる。取込が始まると取込枠は隠れ(「破棄する」で戻る)、記録・反映が終わるとカード(ファイル名など)を消して取込枠が元の状態に戻り、結果は画面下に8秒だけ知らせる。確認の間は、確認の表が上(見出しの行の右端に、文字の案内なしで「記録する」「破棄する」ボタンだけ。押せない理由はボタンにマウスを乗せると出る。変更・取消のFAXは「反映する」)、取り込んだ原本が下に大きく出る(`viewer.js`。ホイールでズーム、ドラッグで移動、「全体表示」・ダブルクリックで幅に合わせる。PDFの描画は pdf.js をCDNから読み込む。読み込めないときはブラウザ標準のPDF表示に切り替える)。読み取り結果の表は、横スクロールなしで全体が見える(行の削除ボタンは無い)。**記入か選択が必要な欄は黄色**で表示し、入力すると消える。「確認が必要な項目」の表は、人が選ぶ必要のある確認だけを出す(自動・工事番号未選択は出さず、下のメッセージに出す)。読み取り結果が表で出る。間違いは表の中で直せる。「原本を見る」で元のFAXを横に開いて照合できる。
  - **工事番号**: 工事に該当しないものは、リストの一番上の「その他」を選ぶ(工事番号・現場名の両方に「その他」と記録。取込一覧の現場名の絞り込みにも「その他」が出る)。行先から、取込一覧の過去の記録で最後に選んだ工事を初期値にする。違うときは、情報シートの一覧から選び直す(現場名が連動)。
  - **照合・確認事項**(表): 車両・運転手情報との食い違い・重複・新規を一覧する。要確認の項目は、対応を選ばないと記録できない。

## 原本の向き(2026-10-23、ユーザー指示。GAS 20261023a)

- 横倒し・逆さまで入れられたFAXは、正しい向きに回して表示し、**Driveにも回したものを保存する**(取込一覧で開く原本も正しい向きになる)。
- 向きは、**画面側で画像から判定する**(`viewer.js` の `detectRotation`。読み取りと同時に行うので待ち時間は増えない)。①長い罫線が横に多いか縦に多いかで、正立・逆さま か 横倒し かを決め、②表(縦線のある範囲)の中心が下寄り・文字(表題・宛名・住所)が上寄りなら正立。ユーザーのFAX 5枚×4方向×PDF/PNG=40通りで全問正解(2026-10-23)。逆さま(180°)は、はっきりしたときだけ回す。
- Geminiにも「回転」を返させている(Code.gs 20261023a)が、実測で横倒し→0、逆さま→270 と外れたため使わない。
- 取り込み中の原本の上に「↺ 左に90°」「↻ 右に90°」ボタン。判定が外れたら手で直せる(保存する原本も回る)。
- PDFは pdf-lib(CDN。無料)でページの向きの設定だけを変える(画質は変わらない)。PNG・JPEGは描き直す。`viewer.js` の `rotateFile`、`app.js` の `setCardRotation`。
- 既にDriveに保存した原本は、回していない(これから取り込む分から)。
- 向きの判定と回転は、**Geminiの読み取りの前**に行い、回した原本を読み取りに送る(横倒しのままだと「神戸107い888」を「し」と読み違えた。回すと正しく読めた。2026-10-23 実測)。

## 速さ(2026-10-21)

- GAS: 情報シートのA・B列とタイムゾーンは、1回の実行で1回だけ読む(日付セルのたびに読み直していたのが主な遅さの原因だった)。Asia/Tokyoの日付は、GASのサービスを呼ばずに計算する。コードを変えたので `CODE_VERSION` を更新(貼り替え→新バージョンが必要)。
- 画面: 取込一覧は、起動時に初期データと同時に先読みし、取込一覧タブ・再取込の判定で同じデータを使い回す。PDFを入れた時点で、OCRと同時に取込一覧の読み込みを始める。

- **原本をすぐ開く(2026-10-23、ユーザー指示)**: 原本の取得(GASの `getFile`)は1回の応答に3〜4秒かかる(公開GASで実測。中身が空の `ping` でも約1.3秒)。そこで画面側で、①取込一覧を出したら、表の上から10個の原本を2つずつ先に読む ②行にマウスを0.15秒止めたら、その原本を読み始める ③読んだ原本はファイルURLごとに覚え、2回目からはすぐ出す ④pdf.js も先に読む。模擬(getFileに2秒)で、先読み済みの行は押してから約0.05秒で原本が出た(以前は約2秒)。GASの変更なし。

## 再取込の防止

読み取ったFAXが、取込一覧に既にある内容と全く同じ(読み取った行すべてが、記録済みの行のどれかと、書かれている項目すべて一致。空欄の項目は比べない)なら、「同じ内容のものです。取込をキャンセルしました」とポップアップを出し(OKで閉じる)、取り込みをやめる。変更FAX・取消FAXの再取込も同じ(取消線の行は、変更前・中止の行と比べる)。取込一覧を読み込めなかったときは、このチェックを省く。

## 追加変更依頼(2026-10-26)

ヘッダー(会社ロゴの左)のピンクの「追加変更依頼」ボタン → 依頼の種類(新規ボタンの追加/既存ボタンの修正/既存ボタンの削除。修正・削除は対象ボタンを選ぶ)・内容・添付1ファイル(10MBまで)・お名前(任意)→「AIに変更指示」。送信後は「アプリの追加変更対応は、数日必要な場合があります」だけを出す。裏で、GASがシート「変更指示」へ1行追記(対応状況=未対応)、添付をDriveの「アプリ作成依頼資料」へ保存、管理者へメールする。

## 取込一覧 ⇔ 車両・運転手情報の連動(2026-10-26)

共通の6項目(手配業者・運送業者・車種・車番・氏名・携帯番号)を一方で直して保存すると、画面が `linkPreview`(GAS)で件数を確かめ、「すべて直す」「この行だけ直す」「キャンセル」を聞く。「すべて直す」のときだけ `link=true` で保存し、GASが同じ組み合わせの行も直す。
- 同じ組み合わせ = 直す前の「車番+氏名+車種」が一致する行(取込一覧は変更前・中止の行も含む)。車番・氏名・車種を直したときも、直す前の値で探す。
- 運送業者の名前を直したときは、同じ運送業者名(書き方の違いは同じとみなす)の、他の運転手の車両・運転手情報の行と取込一覧の記録も直す。
- 備考と、取込一覧にだけある項目は連動しない。1回に直せる行は600行まで(超えると「この行だけ直す」を案内)。
- 車両・運転手情報の削除は連動しない。
