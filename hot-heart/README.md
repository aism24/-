# 試合記録アプリ：GAS × GitHub Pages 分離構成

「試合記録」Webアプリを、**フロントエンド（GitHub Pages）** と **バックエンド（GAS API）** に分離した構成です。

これまではGASのWebアプリ（`doGet`がHTMLを直接レンダリング）をそのまま公開していたため、`script.google.com` ドメインで初回アクセス時に警告バナーが表示されていました。この構成ではUIをGitHub Pagesで静的配信し、GASは**JSON専用API**として呼び出す形にすることで、これを回避します。

## 構成

```
hot-heart/index.html   … フロントエンドのHTML（画面構造のみ）
hot-heart/style.css    … スタイル（レスポンシブ対応）
hot-heart/app.js       … 画面ロジック + GAS APIとの通信処理（fetchでGET/POST）
hot-heart/gas/Code.gs  … GAS側に貼り付けるバックエンドコード（JSON専用API）
```

リポジトリ直下の `index.html` は、旧URL（`https://<ユーザー名>.github.io/<リポジトリ名>/`）に来たアクセスを `hot-heart/` へ自動転送するためのリダイレクト専用ページです。

**「写真をイラスト」機能は今回の分離作業で削除しました。** 画面・CSS・JSとも該当コードは含まれていません。

## 変更点まとめ（旧アプリとの違い）

| 項目 | 旧（単体GASアプリ） | 新（分離構成） |
|---|---|---|
| UI配信 | `doGet()` が `HtmlService` でHTMLを直接返す | GitHub Pagesが静的ファイルとして配信 |
| サーバー通信 | `google.script.run` | `fetch` によるJSON API通信（GET/POST） |
| 背景写真一覧の取得 | `doGet()` 内でテンプレート変数 `<?!= imageIds ?>` に埋め込み | ページ読込み時に `?action=imageIds` へGETして取得 |
| 写真をイラスト機能 | あり | 削除 |

データストア（スプレッドシート・Driveフォルダ）はこれまでと同じものをそのまま使います。IDは変更していません。

## 1. GAS側（バックエンドAPI）のセットアップ

**重要: 既存の本番デプロイ（現在チームが使っているURL）は変更しないでください。** 新しいコードは**新規デプロイ**として発行し、十分に動作確認してから、必要に応じて案内を切り替えます。

1. 既存のGASプロジェクト（このアプリのApps Scriptエディタ）を開きます。
2. `hot-heart/gas/Code.gs` の内容を、既存の `Code.gs` の中身と**まるごと置き換えます**（コピー＆ペースト）。
   - 既存の `index.html`（HTMLファイル）はもう使わないので、そのまま残しても削除しても構いません（`doGet`から参照しなくなります）。
3. 保存後、右上の **「デプロイ」→「新しいデプロイ」** を選択します（既存デプロイの「編集」ではなく、必ず「新しいデプロイ」を選んでください。これにより既存の本番URLはそのまま残ります）。
4. 歯車アイコンから種類を **「ウェブアプリ」** に設定し、以下を指定します。
   - **説明**: 任意（例: `api-v1`）
   - **次のユーザーとして実行**: 「自分」
   - **アクセスできるユーザー**: **「全員」**（フロントエンドから匿名でアクセスするため必須）
5. 「デプロイ」をクリックし、表示される **新しいウェブアプリのURL**（`https://script.google.com/macros/s/xxxxx/exec` の形式）をコピーします。
6. 初回デプロイ時にGoogleアカウントの承認画面が出るので、権限を許可してください。
7. **このURLをClaudeとのチャットに貼り付けてください。** `app.js` の `GAS_API_URL` に反映してGitHubにpushします。
8. コードを修正した場合は、この新規デプロイを編集し「新バージョン」として更新すれば、URLは変わりません。

### 注意点

- GASのウェブアプリはCORSのプリフライト（OPTIONSリクエスト）に対応していないため、`app.js` からのPOSTは `Content-Type: text/plain` で送信し、GAS側で `JSON.parse(e.postData.contents)` として読み取っています。`application/json` を指定するとプリフライトが発生し失敗するので変更しないでください。
- レスポンスは常にHTTP 200で返り、成否は返却JSONの `status` フィールド（`success` / `error`）で判定します。
- 今回、なりすまし投稿を防ぐトークン等の追加認証は入れていません（チーム内利用のため現状維持）。将来的に必要になった場合は `app.js` のPOSTヘッダーに固定トークンを付与し、GAS側でチェックする形で追加できます。

## 2. フロントエンド（GitHub Pages）のセットアップ

1. `hot-heart/app.js` の先頭にある `GAS_API_URL` を、手順1で取得した**新しい**ウェブアプリのURLに書き換えます（このステップはClaudeが担当します）。

   ```js
   const GAS_API_URL = "https://script.google.com/macros/s/xxxxx/exec";
   ```

2. 変更をリポジトリにコミット・プッシュし、mainブランチに反映します。
3. GitHubリポジトリの **Settings → Pages** を開きます。
4. **Source** で以下を設定します。
   - `Deploy from a branch`
   - ブランチ: `main`、フォルダ: `/ (root)`
5. 保存すると数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/hot-heart/` で公開されます（リポジトリ直下は `hot-heart/` への自動転送のみ）。

## 3. 動作確認

1. GitHub PagesのURLにブラウザでアクセスし、ホーム画面（🏀 試合記録）が表示されることを確認します。
2. 「📝 スコアを記録」を開き、対戦相手のプルダウンに既存の対戦相手一覧が表示されること（`getOpponentList` のGET）を確認します。
3. 新しい対戦相手・スコア・写真を入力して保存し、以下を確認します。
   - 保存中のポップアップ（プログレスバー）が表示されること
   - 同名ファイルが既にある場合は上書き確認モーダルが出ること（`checkImageDuplicate` のGET）
   - 保存成功後、結果画面に遷移すること（`uploadImageAndSave` のPOST）
   - スプレッドシートとDriveフォルダに実際にデータ・写真が追加されていること
4. 「📊 結果一覧」から男子・女子それぞれの勝敗数・得失点・一覧が表示されること（`getResults` のGET）を確認します。
5. 「🔥 Hotタイマー起動」を開き、45秒タイマーの動作と、背景写真スライドショー（`imageIds` のGET、`背景写真`シートにデータがある場合）を確認します。
6. ブラウザの開発者ツールのNetworkタブで、各GET/POSTが `status: "success"` を返していることを確認します。
7. 問題なければ、チームメンバーへの案内URLをこのGitHub PagesのURLに切り替えてください（旧デプロイURLは必要なくなるまで残しておくと安全です）。

## トラブルシューティング

- **一覧や結果が読み込めない**: `GAS_API_URL` が正しいか、GASデプロイの「アクセスできるユーザー」が「全員」になっているかを確認してください。
- **写真保存でエラーになる**: Driveフォルダ（`DRIVE_FOLDER_ID`）へのアクセス権限、スプレッドシート（`SPREADSHEET_ID`）へのアクセス権限を確認してください。
- **CORSエラーが出る**: `app.js` のPOSTの `Content-Type` が `text/plain;charset=utf-8` になっているか確認してください（`application/json` にするとプリフライトで失敗します）。
