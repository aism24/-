# 利用記録が利用者に分からないかの点検手順(2026-10-23)

作成者が利用状況を把握するため、各アプリは「利用記録」を裏でスプレッドシートに書いている。
**利用者には記録されたことが分からないようにする**のが方針(ユーザー指定)。新しいアプリを作るとき・記録まわりを直すときは、この手順で確かめる。
修正が必要なときは、案を出してユーザーの承認を得てから直す。

## 1. 記録の送信箇所を洗い出す

```bash
# 画面側: 記録を送る呼び出し
grep -rnoE "action['\"]?\s*[:=,]\s*['\"][a-zA-Z_]*([Ll]og|[Rr]ecord|[Uu]sage|[Aa]ccess)[a-zA-Z_]*['\"]|apiPost\(['\"][a-zA-Z_]*([Ll]og|[Rr]ecord|[Uu]sage)[a-zA-Z_]*['\"]|sendBeacon|log(Download|Open|Usage|AppOpen|PdfDownload)[a-zA-Z_]*\(" <フォルダ> --include=*.js --include=*.html
# GAS側: 記録シートへの書き込み
grep -nE "['\"](記録|利用記録|ログ|履歴)['\"]|appendRow|insertRowBefore" <フォルダ>/gas/*.gs
```

送信のきっかけになる操作(開く・ボタン・ダウンロード・解析完了など)を、アプリごとに表にする。

## 2. 画面に出る表示を確かめる

各呼び出しについて、次を読む。

- 成功したときに、トースト・ポップアップ・文言(「記録しました」「送信しました」など)を出していないか
- `.catch` や `catch` の中で、画面に文字を出していないか。失敗時だけ出る表示は見落としやすい(例: shipping-list-link の「(元PDFの保存・記録に失敗しました)」)
- 記録の完了を `await` で待ち、その間に読み込み中の表示が出ていないか
- 共通の通信関数(`apiPost`・`callServer` など)自体が、ローディングやエラーのトーストを出していないか
- 画面に見える文言全体を grep する: `grep -rnE "['\"\`>][^'\"\`<]*(記録|ログ|送信しました|送信中)[^'\"\`<]*['\"\`<]"`

## 3. 新旧比較(直したとき)

- 修正前のコードを `git archive` で取り出し、Playwright で同じ操作を新旧に行う。
- GAS の応答を「成功」「失敗(ok:false 等)」「通信エラー(route.abort)」「先にポップアップを閉じてから失敗」の4通りに切り替え、**GASへ送る中身**と**画面の表示**を比べる。違いが意図したもの(表示が消えるだけ)であることを確かめる。
- テスト用のPDFは1回だけ作って使い回す(毎回作ると作成日時が入って長さが変わり、送る中身が違って見える)。

## 4. 画面操作では見えないが、調べれば分かるもの(参考として報告する)

- 開発者ツールのコンソール出力(`console.log` / `warn` / `error` に「記録」「logPdfDownload」など)
- ページのソースのコメント(例:「利用記録: ページが開かれたら…」)
- 公開リポジトリの README・docs
- ネットワーク欄の送信そのもの(避けられない)
