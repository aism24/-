# openpyxlのExcel一括処理を速くする手法(マスタ全自動更新、2026-10-16)

`docs/know-how.md` の索引項目「openpyxlのExcel一括処理+共有フォルダ問い合わせを速くする」の詳細。
対象はローカルのPythonスクリプト(複数のExcelを読み、突合して保存し、共有フォルダへコピーし、リンク先の存在を確認する)。

## 実測の内訳(7工事の合計88秒。逐次処理)
| 工程 | 割合 |
|---|---|
| 記録用Excelの読込 | 27% |
| リンク先の存在確認(フォルダ一覧の取得) | 23% |
| 実マスタの読込 | 22% |
| 記録用Excelの保存 | 16% |
| 突合 | 12% |

コードの矛盾・デッドコードは主因ではなかった。openpyxlのファイルの読み書きと、共有フォルダへの問い合わせ待ちが大半で、7件を1件ずつ処理していたのが効いていた。

## 効いた4つ(91.8秒 → 16〜17.5秒)
1. 独立した案件ごとに `ProcessPoolExecutor` で並列(上限6)。openpyxlの読み書きはCPUを使うため、スレッドでは速くならない。子プロセスの `print` と警告は `redirect_stdout` / `warnings.catch_warnings` で文字列に取り込み、親が元の順に表示する。`--serial` で逐次に戻せるようにしておくと比較に使える。
2. 共有フォルダの一覧取得(`os.listdir`)は待ち時間が大半なので、`ThreadPoolExecutor` で8並列(531フォルダで13.5秒 → 3.1秒)。判定の順番と結果は変えない(集める → 並列で取得 → 元の順に判定)。
3. 参照専用のExcelは `load_workbook(read_only=True, data_only=True)` で必要なシートだけ読む(約2倍速)。必要なAPIだけの小さなラッパークラスで包み、読んだら閉じる。
4. 変更が無ければ保存しない(変更の有無を関数が返す)。コピーは先方のサイズと更新日時が同じなら省く(`shutil.copy2` は更新日時も引き継ぐ)。前回のコピーに失敗していた場合は、日時が違うので自然に再コピーされる。

## 進め方(効果の確認方法)
1. 本番に触れない作業コピーで旧版を実測する(保存先の設定を作業フォルダへ向ける。読み取りだけのファイルは本番を読む)。
2. 工程ごとの内訳を出し、割合の大きいものから対策する。
3. 旧版と新版で、画面の出力・一覧・生成物・保存したExcelの中身が一致することを比較する。行の削除や着色など、わざと崩した入力でも結果が一致することを確認する。
4. 再実測する。サーバーの応答でぶれるので、複数回測って幅で報告する(16.1 / 16.5 / 16.6 / 17.5秒、重い回は21〜25秒)。

## 落とし穴
- `cell.fill` などは参照のたびに別オブジェクトが返ることがあり、`id()` をキャッシュのキーにすると誤判定する(黄色の塗り直しが漏れた)。ブック内の通し番号 `cell._style.fillId` を使う。
- 並列化で、子プロセスが共有のグローバルリストを `clear()` すると、逐次モード(同じプロセス)では親のリストが消える。退避して戻す。
- 図番が空の行の突合キーに小数を含めると、保存して読み直したときに下位の桁がずれて一致しなくなり、毎回「追加+削除」になる。有効10桁に丸めて比較する。
- 「変更なしなら保存を省く」では、前回の着色が残っているだけでも変更とみなす(着色リセットも変更に数える)。
