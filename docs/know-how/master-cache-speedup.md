# 大きなマスタJSONを速く配る・速く作り直す(GAS+Vercel+ブラウザ保存)

出荷リスト(shipping-list-link、PR #882・#884、2026-10-23)で使った手順。GASがDriveのExcel等から大きなJSON(数MB)を作り、画面が毎回それを取得するアプリにそのまま流用できる。

## 0. まず実測して、どこで待っているかを分ける
- 経路ごとに1回ずつ `curl -w "%{http_code} %{time_total}s"` で測る: 中継API(CDN HIT/MISS は `x-vercel-cache` ヘッダー)/ GAS直接の本体 / GASの軽い状態確認。
- 出荷リストの実測: CDN HIT 0.29秒 / CDN MISS 16.2秒 / GAS直接 8.9秒(1.4MB)/ 状態確認 2.6秒。画面は中継を10秒で打ち切ってGAS直接へ切り替えるので、MISS時は合計約20秒。
- 作り直す元データ(Excel)の更新時刻と、作り直した時刻を突き合わせる。毎朝の自動更新がExcelの差し替え(7時台)より前(6時台)に走っていて、最新が反映されていなかった。

## 1. 画面: 取得したJSONをブラウザ(IndexedDB)に保存し、次回はすぐ使う
- 開いたら保存分を読み、あれば表示して待ちのポップアップを閉じる。最新かどうかは裏で確認する(ユーザーが選んだ「案1」)。
- 裏の確認は、GASの軽い `?action=info`(更新日時だけを返す。Driveを読まない)。表示中のJSONの `updated` と違うときだけ、本体を取り直して差し替え・保存する。
- 取り直すURLに版を付ける: `api/links?v=<更新日時>`。CDNは版ごとに保存するので、2台目以降のPCはCDNから0.2秒前後で取れる。
- 確認中に「最新を取得」ボタンで差し替わっていたら、裏の結果で上書きしない(開始時の `cur` と同じかどうかで判定)。
- IndexedDB が使えない環境(シークレットウィンドウ等)では null を返して従来どおり取得する。open が固まったときのため3秒で打ち切る。
- 保存するのは、サーバーが返した圧縮形式のままにする(展開は表示のときに行う)。
- 実測(本番、Playwright): ポップアップが閉じるまで 1回目1.3秒 → 2回目0.8秒。模擬環境で状態確認の応答を3秒遅らせても、閉じるのは約0.6秒(確認を待たない)。

## 2. GAS: 作り直しは、変わった元ファイルだけ読む
- 作り直すたびに、元ファイルごとの抜き出し結果を Drive に1つのJSONで残す(キー=ファイルID、値={name, modified, 抜き出し結果})。
- ボタンでの作り直しでは、名前と更新日時が前回と同じファイルは読まずに前回の結果を使う。毎朝の自動更新は安全のため全件読む。
- 残した結果が無い・壊れているときは全件読む(結果が壊れることはなく、遅くなるだけ)。
- まとめる順番は、毎回 `masterFiles_()` の並び順にそろえる。差分読みと全件読みで出力が1文字も違わないようにするため。
- 作り直した直後は、GAS側キャッシュ(CacheService)を消すだけでなく、新しいJSONで作り直しておく。直後の取得がDrive読みにならない。
- ログに「読み直したファイル数と、ファイルごとのms」を出す。本番の実測はここで取る。
- `CODE_VERSION` を定数で持ち、`?action=ping` で返す。貼り替え・デプロイ後に版を確かめてから報告する。

## 3. テスト: GASは Node の vm で模擬環境を作り、旧コードと新コードを比べる
- DriveApp・Utilities(unzip・gzip・base64)・PropertiesService・CacheService・LockService を偽物にする。Code.gs を `vm.runInContext` で読み込む。
- Excelは、unzip後のXML(workbook・rels・sheet・sharedStrings)を文字列で作れば足りる。本物のzipは要らない。
- 確認項目:
  - 旧と新の全件作り直しが一致する(`updated` 以外)。
  - 差分読みの結果と全件読みの結果が一致する。ファイルの追加・削除・改名、残した結果の破損でも同じ。
  - 読み直したファイル数(unzipの呼ばれた回数)。
  - 件数が9割未満のときの中止が、旧と同じ応答になる。
- 画面は Playwright で `page.route` を使い、中継とGASを偽の応答にする。比べる場面: 初回 / 2回目 / サーバー側が新しい版 / 確認の失敗 / ボタン / IndexedDB不可。
- PDFの照合は、同じPDFを使い回して、旧と新でリンク(位置・URL)・ポップアップ・NG一覧を比べる。
- 気づいた不具合: 圧縮関数が重複(配列の値)を1つの文字列につないでいた。配列は要素ごとに圧縮・展開する。

## 4. 隠しボタン: ロゴを5回続けてクリックすると、そのPCだけ表示
- 共通ボタン to-launcher.js は、自分を読み込んだ script タグ(`document.currentScript`)の data 属性から設定を読む。なので、後から `document.createElement('script')` で同じ属性を付けて差し込めばそのまま動く。
- クリックの間隔が1.5秒以内なら回数を数え、5回で表示して localStorage に記憶する。もう一度5回で記憶を消して読み直す(to-launcher.js は消されても入れ直す作りのため)。
- 全員に戻すときは、コメントにした元の script 行を戻すだけで済むようにしておく。
