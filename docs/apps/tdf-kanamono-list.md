# 金物リストアプリ(tdf-kanamono-list)の仕様メモ

TDF(実寸法師)の鉄骨図面から、製品ごとの金物(切板・山形鋼)リストを作り、Excelで出すアプリ。
2026-11-19にユーザーと様式・拾い出しルールを決め、同日に `tdf-kanamono-list/` を実装(構成・セットアップは `tdf-kanamono-list/README.md`)。
回帰テスト: 非公開リポジトリ `aism24/test-tdf` の `kanamono/`(7図面と前回値)。`node kanamono/run.js <aism24/->/tdf-kanamono-list/extract.js` で全件OKを確かめてからマージする。図面と工事略称の表は test-tdf の README.md。
公開リポジトリのため、工事名・工事番号・実図面はここに書かない(検証図面は「検証図面A」と呼ぶ)。

- GAS → GitHub → Vercel(管理用のDriveフォルダ・スプレッドシートはユーザー作成済み。IDはここに書かない)
- 本番: https://tdf-kanamono-list.vercel.app/(2026-11-20 公開。Vercelプロジェクト名「-tdf-kanamono-list」。状態は docs/vercel-status.md)
- tottori-production-status から飛ぶ先(KANAMONO_URL)は 2026-11-20 から金物リストの本番。tottori は GitHub(raw.githack)で確認し、本番(Vercel)は完成までデプロイしない(ユーザー指示)。
- ① アプリ起動 ② サーバー(TDFの置き場所)を指定=Excelのハイパーリンク用 ③ TDF取込(別フォルダからも追加可。ただし同じ工事だけ)
- ④ 金物リスト一覧をテーブル表示。図番クリックでPowerShell経由で実寸法師を開く ⑤ ハイパーリンク付きExcelダウンロード
- **除外したもの(下の「対象外」)は、アプリでは「除外一覧」として表示する**(黙って捨てない)

## 画面の仕様(2026-11-19決定分)
- 取込のボタン(①のサーバーボタン・②)は、下の表の幅に合わせて均等に並べる。取り込んだTDFの一覧はフォルダの列を出さない(長いため)。
- 見た目は **tdf-master-web に寄せる**。ヘッダーの会社ロゴ・会社名はいつも通り(tdf-master-webと同じ)。「← アプリ一覧へ」(共通 to-launcher.js)。
- **工場の選択**: 本社・夢前・鳥取のボタン(tdf-master-web と同じ)。Excelの様式は工場ごとに変えられる作り(`excel.js` の FORMATS。2026-11-19時点は3工場とも同じ様式)。
- **工事の選択**: スプレッドシートの工事番号・工事名のリストから選ぶ。選んだ工事番号はブラウザに記憶し、次回は自動で選ぶ。
- **利用記録**: 起動では記録しない。**工場と工事を選んで「開始」を押したときに記録する**(利用者に分からないように。`docs/know-how/usage-log-hidden-check.md`)。
- **同じ工事の判定**: 図面(TDF)の表題欄の**工事名**で比べる。違う工事のTDFは取り込まない。
- **図番クリック**: `jissun://` のような独自リンク + パソコン側のPowerShellの設定で実寸法師を開く(jissun-open と同じ仕組み)。社内で実寸法師が正しく開くことを確認済み(2026-11-20 ユーザー確認)。
- **枚数の修正**: 自動で拾った枚数を、人が画面で直してからExcelに出す。
- **除外項目はExcelに出さない**。取込のときに除外したものがあれば、取込後にポップアップで「〇〇は対象外のため入れていません」と出し、OKボタンで閉じる(2026-11-21 ユーザー指示で文言変更)。〇〇は**除外の種類だけ**(例「吊りピース・ネット受けピースは対象外のため入れていません」。製品名・数は出さない)。
  除外の対象(2026-11-19時点): スプライスPL・フィラーPL・吊りピース・ネット受けピース・サヤ管・現場付けの製品。サヤ管は2026-11-20から、サイズ・長さ・本数が分かれば金物リストに入れる(下記)。
- **サーバー(TDFの置き場所)の指定**(2026-11-19。ユーザーのイメージに合わせて決定): ①のサーバーボタン(「① 本社サーバー」「① 鳥取サーバー」。押した方以外はリセットまでグレーアウト)でサーバーを選び、その「①進行中工事」を一度だけ選んで覚える → 「② ファイル選択(何度でも可能)」(薄い緑)は ①進行中工事 から開くファイル選択の画面でTDFを選ぶ → 選んだファイルの ①進行中工事 からの位置と設定シートF列のパスでリンクを作る。パスの手入力・工事フォルダを全部たどる方式はやめた(たどると数百フォルダで待たされた)。
  「② ファイル選択」の画面は、前回選んだファイルのフォルダから開く(2026-11-19 ユーザー指示。ブラウザに最後の1つを覚える)。前回とサーバーが違う・前回のファイルが今の ①進行中工事 の外のときは ①進行中工事 から開く。
  ①進行中工事が正しいサーバーのものかは、直下の目印ファイル「_本社サーバー…」「_鳥取サーバー…」で確かめる(tdf-master-web と同じ)。覚えたフォルダの目印が違えば覚え直し、別のサーバーとして覚えたのと同じフォルダは選べない。「選んだサーバーの①進行中工事を選び直す」で手で覚え直せる(2026-11-19。本社のフォルダを鳥取として覚えてしまい、鳥取の図面にリンクが付かなかったため)。
- **管理用スプレッドシート「製品別金物一覧アプリ」**(Driveのフォルダは `docs/drive-folders.md`。IDはここに書かない):
  - シート「設定」: A列=工事番号、B列=工事名(1行目は見出し)。画面の工事リストはここから読む。
  - 同じシート「設定」のE列=サーバー名(例 本社・鳥取)、F列=ファイルパス(各サーバーの「①進行中工事」フォルダの絶対パス)。工事の行とは独立した表。サーバーのIPアドレス・パスはここに書かない。
  - 画面: tdf-master-web と同じく「図面があるサーバーを選んでください」でE列から選ぶ → F列のパスを基準に「📁 フォルダを選ぶ」で選んだフォルダの絶対パスを組み立て、Excelのハイパーリンクと図番クリック(jissun://)に使う。
  - シート「記録」(見出し A=日時・B=工事名・C=工場・D=シート名): 工場と工事を選んで「開始」を押したときに A〜C を記録(工事名は設定シートの略称)。起動時は記録しない。
    **Excelをダウンロードしたときも、そのたびに新しい行を足す**(A=日時・B=工事名・C=工場・D=データシートの名前)。
    どちらの記録も**2行目に挿入し、新しいものが上**(いつものやり方。既存の行は下へずれる)。
  - データシート(いつものやり方。tdf-master-web の addDataSheet_ と同じ考え方): ダウンロードしたExcelと同じ内容(製品ごとの表と総まとめ)を、名前「MMdd_追番」(例 今日の1回目=`1119_1`、2回目=`1119_2`)のシートとして最右端に追加。
    このデータシートは**新しい10枚だけ残し、11枚目を作るときに一番古いものから消す**。名前に年が無いので、古さは名前でなくシートの並び(左が古い)で判断する。
  - 注意: 設定シートの工事名は略称で、図面の表題欄の工事名(正式名)とは一致しない。Excelの工事名は図面から読む。


## 自動の拾い出しの仕組み(tdf-kanamono-list/extract.js)
- 製品 = 「製品名 符号 N台」の行(符号の無い行=現場付けは拾わない)。行の高さが近い製品は同じ図(立面図・平面図)。並びは上の図から、同じ図の中は製品名の番号順。
- 断面の表記(「GPL-9 / KG1」)は、表記の下の引出線と符号の位置で組にする。どの断面図かは下の見出し「A SEC」で決まる。
- 断面の数 = 立面図の旗(文字の右の縦線)の数。旗は左の板を見る(板厚が断面の表記と合う板。左800・右400以内)。
  同じ場所を複数の断面で描いていれば、各符号はその中で一番少ない枚数(反対側がガセットなら片側)。
  立面図で板が描かれていて旗の無い場所は、同じ板厚の旗のある場所と同じ断面とみなす(例: PL-12の中間スチフナー6か所)。
  板が描かれていない場所の旗(EV鉄骨取合など)は、旗の数×表記の数。断面図の中の断面記号(C断面の中のE)は親の断面の数。
- 立面図に直接書いた表記(PL-12 / KGR64)は1つにつき1枚。FBは表記の寸法の□の数。山形鋼は立面図の同じ高さに3本以上並ぶ線、溝形鋼は平面図の断面寸法と同じ長さの線の組。
- 備考 = 断面の副題(**その断面の板すべてに付ける**。2026-11-19ユーザー決定。符号を描いた断面の副題が2種類以上なら付けない)と「めっき」(引出線のそばの(めっき)、または符号の番号のすぐあとの M。「NG121M」「NHG143MK」の MK も。2026-11-21 ユーザー指示、EA1-RG-01)。FBは「デッキ受け」。
- 継手の表記(〜J〇)がある断面の形鋼(束・吊材・胴縁受け)は拾わない。
- 2026-11-21 ユーザー確認、EA2-3G-08: 旗の上の「(x4)」などの書き込みはあてにせず(参考のみ)、立面図・平面図の絵で数える(ユーザー指示)。立面図の板に当たらないコン止めの断面は、旗のそば300以内に平面図の板が無ければ500以内で「長さ = 断面図の寸法 − ウェブ厚の半分」(620 − 19/2 = 610.5)にぴったり合う板を探して数える(か断面 NNGNR1・NNGNR2 1 → 4)。ひらがな・カタカナの断面の見出しのすぐ上(1500以内・横1000以内)の表記は、図の範囲に入っていても断面図の表記として読む(NNGNR2 に備考「コン止め」)。

## 拾い出しルール(決定)
- 対象: 切板(PL・GPL・FB)と、セパ溶接固定用下地などの山形鋼(L-)。本体の鋼材(H・SH・BTの本体)は載せない。
- **対象外(除外一覧へ)**: スプライスPL・フィラーPL・吊りピース・ネット受けピース・サヤ管・**現場付けの製品**(例: 梁の両端に現場で付けるBT)。
- 別の製品として取り合う部材(束・吊材のH形鋼やL形鋼=P25・EP25・P9など、ボルトで付く胴縁受けの形鋼=DCJ1など)は拾わない。**そこに付くガセット(KG〜)は拾う**。
- 形鋼の受材(山形鋼L-、溝形鋼C-。例 間仕切受材 C-60x30x10x2.3)は「サイズ|長さ」で拾う。長さは平面図・立面図の線で測る。
- 寸法線(例: 部材の横の「30」の寸法の線)は部材ではない。符号・文字の無い線を部材と誤認しない。
- 同じ形の板は、文字が1か所だけでも**図形の数で数える**(例: FB-6x65x255 は継手の片端に上下2枚=1台4枚。文字は上側だけ)。
- 山形鋼は断面図のとおり片側(両側と書かれていなければ片側)。長さは立面図の線を1本ずつ測る(寸法の文字と一致を確認)。
- 工場で付く部材は、その製品で拾う(例: 大梁の上のBT-340は工場で付くので大梁で拾う。現場付けのBTは除外)。
- スチフナーは断面図のとおり両側。ただし**反対側にガセット(GPL)が来る位置(B断面のような小梁の取合い)は、スチフナーは片側**。
- 吊りピースの見分け方: 上フランジ下の300×230程度の箱(吊りピース(KG1A)などの記載の位置)。除外一覧へ。
- ネット受けピースの見分け方: 下フランジに並ぶ小さな部材(寸法列の位置に描かれ、「K8(両側)」の記載があるもの)。レイヤ「ネット受けピース」もある。除外一覧へ。
- 枚数(本数) = 1台あたり × 台数。
- 参考(除外になったが判断の知見): フィラーの「内」はウェブの両側で2枚。

## Excel様式(決定)
- ファイル名: `<図面番号>_金物リスト.xlsx`(図面番号は図面の表題欄に書かれたもの。例 `B1M2G-001_金物リスト.xlsx`。TDFのファイル名ではない)
- TDFを複数取り込んだときは**1つのExcelにまとめ**、**総まとめは取り込んだ全TDFの合計**
  - ファイル名: `<工事番号>_<年月日>_<時分>_金物リスト.xlsx`(例 `26-17_20261119_1530_金物リスト.xlsx`。日時はダウンロードした時刻)。TDFが1つなら `<図面番号>_金物リスト.xlsx`
  - 総まとめの見出し: 「取り込んだTDF全ての総まとめ」
  - 製品の並び順: 図面番号順に並べ替え、同じ図面の中は**図面の上段の製品から順**(チェックしやすいため。例 GJが上段ならGJ→GI)。同じ記号の中は番号を数として比べる(GJ9→GJ10→GJ12)
- 製品の「サイズ」は本体の主材だけ(例: BT-340が載る大梁でも SH-700x300x14x22 だけ書く)
- シート「金物リスト」1枚。A〜D列 幅20.625、E列 幅9。フォント ＭＳ Ｐゴシック。
- 1行目: 「金物リスト」(14pt太字、下罫線細) / 2行目: 工事番号(太字) / 3行目: 工事名(図面から読む。B:Dを結合) / 4行目: 空き。
- 製品ごとのブロック(製品の番号順):
  1. 「図面番号|製品名|サイズ|長さ（mm）|台数」(薄黄 FFFFCC、外周の左右と上は二重線)
  2. その値の行(薄黄、下は太線)。サイズ・長さは本体の鋼材。**行の高さは倍(28.5)・縦方向は中央揃え。ハイパーリンクは**図面番号と製品名の両方のセル**に付け、青(0000FF)太字・下線**
  3. 「サイズ|切板名（長さ）|枚数（本数）|備考」(水色 DDEBF7・太字)
  4. 明細(罫線細、左右の外周は二重線)。**並びは GPL → PL → 鋼材(FB・L・Cなどの形鋼)。それぞれ板厚の小さい順、同じ板厚は符号の番号順(KG23→KG116M→KG213)。GPLの行はA〜C列を太字**。符号がある板は「GPL-9|KG1」、寸法で書かれた板は「FB-6x65|255」「PL-12x199|KGR222M」、形鋼は「L-50x50x6|長さ」。備考は断面図の副題や用途(例「デッキ受け」「セパ溶接固定用下地」「EV鉄骨取合」「胴縁受け」「ぶどう棚」「止水PL」「間仕切受材」)と「めっき」(符号の末尾Mや図の「(めっき)」)。
  5. 小計(灰 F2F2F2・太字、下は二重線。板と山形鋼は分けずに合算) → 空行(高さ15)
- 最下部: 「総まとめ」(12pt太字) → **種類別の表を GPL → 他(PL) → 鋼材 の順**。各表は 種類名(12pt太字) → 見出し(水色) → 合算(黄 FFF2CC。並びは製品の表と同じ。GPLの行は太字) → 空行。**合計の行は付けない**。FBは鋼材の表だけに入れる。(2026-11-19変更。以前は1つの表+合計)
- 行の高さ: 1行目17.25、製品の値の行28.5、ブロックの見出し・一覧見出し・小計・総まとめ見出し14.25、空行15(総まとめの直前だけ14.25)、ほかは既定13.5。
- 印刷: A4縦・横1ページに収める(縮小96%)、上下余白2.5cm・左右1.9cm、1〜4行目を毎ページ印刷。
  **各ページの先頭は必ず製品名のブロックか総まとめ。ブロックの途中で改ページしない**(ブロック単位で収まらなければ直前の空行の後で改ページ)。
  **総まとめは必ず新しいページから始める**(製品のリストと同じページに載せない)。総まとめが長いときは、種類別の表(GPL・他・鋼材)の途中で切れないように表単位で改ページする。

## コードの精査と最適化(2026-11-21 ユーザー承認)
- 柱の図面の板の数え方(extract.js columnItems): 平行な同じ長さの2本の線の組を、断面の記号と板厚ごとに1回だけ、長さ順に並べて長さの差が1以内の線どうしだけ比べる(以前は約3,000本の総当たりをマークごとにやり直していた)。結果は同じで、柱3図面 826ms → 100ms、16図面の合計 1,170ms → 432ms。
- 工事リスト: 前回GASから読んだもの(localStorage `tdf-kanamono-list:settings`)をすぐ出し、裏でGAS(1〜4秒)から読んで変わっていれば置き換える。GASが読めなくても前回の工事リストで続けられる。
- 長さの Python(約5MB)は、工場・工事を選んで開始したとき(次の加工予定はお知らせのとき)に裏で読み始める(preloadPy)。失敗しても何も出さず、取り込むときに読み直す。
- 工事名が違うTDFは、長さ(Python)を読む前に止める。次の加工予定で図番から探すとき、工事のフォルダ探しは工事ごとに1回。
- 画面で枚数・備考を直したときは、その欄・小計・総まとめだけ書き換える(全体を描き直さない。Tab で次の欄へ移れる)。
- 次の加工予定から作った画面の「Excelダウンロード」は、最初に届くExcelと同じ形(シート１の一覧+工事ごとのシート)で、画面で直した数を入れて作り直す(以前は1枚の「金物リスト」で工事番号が空欄だった)。
- 取り込んだTDFの一覧も、下の金物リストと同じ並び。
- 不具合の修正: 切板名が空欄の金物(スリーブ 150S など)が同じサイズで2行になると(備考を直したときなど)、並べ替え(natKey)が止まって画面が更新されず、Excelも作れなかった。
- 使っていないコード(extract.js の near、excel.js buildPlan の factory 引数)を削除。
- 画面の通しテストは test-tdf の kanamono/app-test.js(README 参照)。extract.js を直したら run.js、app.js・excel.js を直したら app-test.js も全件OKを確かめる。
