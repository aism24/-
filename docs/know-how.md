- やり方: `api/data.js` でGASを取得(最大3回リトライ)、`Cache-Control: public, s-maxage=300, stale-while-revalidate=86400`。画面はlocalStorageの前回結果を即表示→裏で更新。失敗時だけGAS直接へフォールバック。

### 自動デプロイを止めたまま公開する
- 効果: push・マージのたびのデプロイ消費を0に(daily-reportで確認)
- やり方: アプリのフォルダに `vercel.json` `{ "git": { "deploymentEnabled": false } }`。公開時だけ `create_deployment`(「デプロイして」の指示があったときのみ)。
- 注意点: Ignored Build Stepは `-- .` と書く(`-- ./<フォルダ>` は常にスキップ)。teamIdは渡さない(403)。
- 使ったアプリ: daily-report, sonekibunki, cost-insight, tori-robo, app-launcher

### GitHub上での画面確認(Vercel枠を使わない)
- 効果: 確認のたびのデプロイが不要
- やり方: `https://raw.githack.com/aism24/-/<branch>/<フォルダ>/index.html`(jsDelivrはHTMLがtext/plainで返るので不可)。
- 注意点: 反映ラグあり。JS/CSSに `?v=<目印>` を付けて毎回更新し、curlで目印が一致してから案内する。
- 使ったアプリ: 全アプリ共通

### GAS Webアプリの「Failed to fetch」(CORS error)と、失敗時の無限再取得(daily-report、10/6)
- 症状: 起動時に「データの取得に失敗しました: Failed to fetch」。GAS実行数は全件「完了」。ネットワークタブは `exec` が「302→CORS error(1秒未満)」で、失敗の分だけ実行数に `doGet` が出る(受取URLが `/exec` へGETで戻され、HTMLにCORSヘッダーが無い)。
- 原因(コードで確認): 総務建築の取得失敗→`renderR5Preview`→`computeR5Groups_`が再取得→失敗…の無限ループ(9秒で293回を再現)。実行数が勝手に増え続ける。タブを閉じると止まる。
- 対処(PR): 失敗フラグで自動再取得を止め、読み取り専用の起動時5件に再試行(最大3回)を追加。jsdom+fetch差し替えで修正前後を比較(成功時は同一、一時失敗は回復、全失敗でも有限回)。
- 注意点: Google側が受取URLを戻す理由は未特定。curlでPOSTを再現するときは `-X POST` を付けない(`-L` で405になる)。「再実行する仕組みは無い」とgrepだけで決めつけない(間接呼び出しのループを見落とした)。
- 使ったアプリ: daily-report

### GASの不調(404・保存エラー・取得失敗)の切り分け
- 効果: 不要なコード変更を避けられた(404の件はPRをrevertして元に戻した。#426→#427)
