## データの流れ(既存アプリは無改変)

新しいGASが、既存2アプリの公開APIを**読み取りのみ**で呼び出して集計します。

| データ | 取得元 |
|---|---|
| 生産重量(工事×工場×日) | 生産管理ダッシュボード(production-management)の `getData` |
| 工数(工事×所属×日) | 日報全期間集計(daily-report)の `getAllDailyReportRows`(アーカイブ横断済み) |
| 工事No・工事名 | 日報全期間集計の `getMasterData`(工事ID→工事No) |

集計結果は `_cache_analysis.json`(管理用スプレッドシートと同じフォルダ)に保存し、画面はこれを読むだけです。
毎朝6時台のトリガーと、画面右上の「今すぐ更新」で作り直します。単価・目標などの設定を変えても再集計は不要です(画面側ですぐ再計算)。

## 計算方法

- 人工 = 作業時間 ÷ 8h(事務・工場とも全員分)。1t当たり人工数 = 人工 ÷ 生産重量
- トン単価 = 契約金額 ÷ 契約総重量(「工事単価」シートC列。未入力なら生産実績の総重量で代用)。契約金額が未入力の工事は売上0円として計算し、画面に警告を出す
- 「工事単価」シートの保存はA〜D列を工事No単位で更新・追記するだけで、行の削除やE列以降(トン単価の計算式など)の書き換えはしない
- 売上 = Σ(工事ごとの生産重量 × トン単価)
- 費用は配分率(初期値 人件費30%・変動費40%・固定費15%・利益15%)で割り付け、実額を入れた項目は実額で計算
  - 基準売上 = 実績売上(目標は「利益目標額 = 売上 × 利益率」の1つだけ。月間目標は使わない)
  - 人件費単価 = 人件費率 × 基準売上 ÷ 基準人工 / 固定費 = 固定費率 × 基準売上 / 変動費単価 = 変動費率 × 基準トン単価
- 損益分岐生産量 = 固定費 ÷ (トン単価 − 変動費単価 − 1t当たり人件費)
- 目標売上額 = 利益目標(売上×利益率)を達成するトン数 × トン単価
- 工事に結び付かない工数(設定の「共通扱い工事No」、工事マスタに無い工事ID)は「共通」に計上。工事別分析で重量比按分の表示に切替可

## GASのセットアップ(初回のみ)

1. Googleドライブで新しいスプレッドシート「生産損益分析」を作成(置いたフォルダにキャッシュが作られます)。
2. 拡張機能 → Apps Script を開き、`gas/Code.gs` の内容を `コード.gs` に貼り付けて保存。
3. プロジェクトの設定(歯車) → 「appsscript.json をエディタで表示する」をON → `appsscript.json` の `timeZone` を `Asia/Tokyo` にする。
4. プロジェクトの設定 → スクリプト プロパティに次の2つを追加:
   - `VIEW_PASSWORD` … 閲覧用パスワード
   - `EDIT_PASSWORD` … 設定保存用パスワード
   - 詳細版は閲覧用・編集用パスワードが必要。シンプル版は閲覧用パスワード無しで開ける(2026-09-29〜。`REQUIRE_PASSWORD`=true)。
5. エディタで関数 `setupTrigger` を選んで実行(権限を承認)。毎朝6時台の自動集計が登録されます。
6. デプロイ → 新しいデプロイ → 種類「ウェブアプリ」、次のユーザーとして実行「自分」、アクセスできるユーザー「全員」→ デプロイ。
7. 発行されたURLを `app.js` 先頭の `GAS_API_URL` に設定する(設定済み: 2026-09-25)。

設定シート(基本設定・工事単価・費用設定)は初回アクセス時に自動作成されます。
