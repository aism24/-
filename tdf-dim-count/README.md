# 実寸データより長さと本数集計(tdf-dim-count)
実寸法師(.tdf。14MB級のOLE複合ファイルの原本も可)から、**選択したレイヤ**の数値テキストと、同じ長さの線の本数を調べる静的アプリ。ブラウザ内で処理(サーバー不要)。
- 条件: レイヤ=選択(番号の完全一致)。数値テキスト(参照も含む)の値ごとに、近い長さの線を最寄りの値へ割り当て、**テキストの数=線の本数**の値だけを集計(不一致は対象外として別表示)。角度は問わない(0/90/180度も対象)。
  - 長さの許容はテキストの小数の桁で決まる(`core.js` の `tolOfText`: 0.5×10^-桁+0.005。整数なら±0.505mm、小数1桁なら±0.055mm)。割合(%)の許容は無い。
- **集計のしかた(2026-10-23〜)**: 起動時(とリセット後)は中央に「集計方法を選択してください」と ① 通常拾い出し / ② ブロック分け のボタンだけを出し、選ぶと手順①〜③の画面になる(2026-10-25〜。選ぶまではドラッグ&ドロップも受け付けない)。その後は画面上部で切り替えられる。
  - ① 拾い出し: 上の条件で、寸法(テキスト)ごとの本数。長さのまとめ(±10/20/30)あり。
  - ② ブロック分け製品名で仕訳け: ①で集計対象になった寸法値テキストと、同じレイヤの数値でないテキスト(製品名)を、**互いに最も近いもの同士**で1対1に組にする(`core.js` の `blockNames`)。表は「ブロック|製品名|本数|長さ|ブロック入り製品名」。製品名テキストを最初の「_」で分け、左=製品名・右=ブロック(例 `5HBR32K-9M_A-4` → `5HBR32K-9M` / `A-4`。先頭の数字も含めテキストのまま)。1つの製品名に複数の長さがあれば「,」区切り。並びはブロックの昇順→製品名の昇順で、ブロックの最後に「小計」行(画面・Excelとも)。組にならない寸法と「_」の無い製品名は表に出さない。Excelも同じ列(シート「ブロック分け」)。
- 仕組みは `core.js` 冒頭コメントと `docs/know-how.md` 参照。
- 回帰テスト: `node tests/tdf-dim-count/run.js`(`core.js` を変えたら必ず実行)。正解値は原本のGEN=56種類・592本、TB見本=9種類・16本、②のTB_ブロック分け=48種類・224本など(`tests/tdf-dim-count/README.md`)。
- `vercel.json` で自動デプロイ停止。本番反映は「デプロイして」の指示時のみ `create_deployment`。

## 利用記録(GAS → スプレッドシート「tdf-dim-count」)
- シート「記録」: A:アプリ起動日時 / B:ダウンロード日時 / C:ファイル名 / D:指定レイヤ / E:総本数(2026-10-23〜)。
  - アプリを開いたら2行目に1行入れてAを記録(**常に2行目が最新の起動**。下に行くほど古い)。その起動でExcelをダウンロードしたら同じ行のB:Eを記録。ダウンロードしなければB:Eは空欄。
  - 同じ起動で2回目以降のダウンロードは、その起動の行のすぐ下に1行(Aは同じ起動日時)。起動の行は、行の開発者メタデータ(画面に出ない目印。キー `tdfSession`)で探す。
  - 起動の行が見つからない(古い版のアプリ・起動の記録に失敗)ときは、2行目にAを空欄でB:Eを記録。
  - GASの版: `gas/Code.gs` の `CODE_VERSION`(/exec を開くと `version` が返る)。
- 送るのはファイル名・レイヤ名・総本数だけ(TDFの中身は送らない)。記録に失敗しても、抽出・Excel出力は止めない。
- セットアップ: スプレッドシートの「拡張機能→Apps Script」に `gas/Code.gs` を貼り付け → デプロイ(ウェブアプリ、実行=自分、アクセス=全員)→ `/exec` のURLを `app.js` の `GAS_URL` に設定 → 本番デプロイ。`GAS_URL` が空の間は記録しない。
- スプレッドシート「tdf-dim-count」の場所は、Driveの引き継ぎ書(保存先フォルダ内)を参照(公開リポジトリのため、IDはここに書かない)。
