# PDF差分解析アプリ

アプリを開くとまず「表」「文章」「図面」の3種類から解析したい種類を選び、
その後新旧2つのPDFをアップロードすると、選んだ種類の方式で変更箇所を色付けして
新旧を並べて表示・PDFダウンロードできるWebアプリ。ヘッダーのロゴ左側の
「ホームに戻る（種類変更）」ボタンで、いつでも種類選択画面に戻れる。

元になった検証用ツール(`pdf_table_diff.py` / `pdf_image_diff.py` / `pdf_text_diff.py`、
Python+PyMuPDF)のアルゴリズムを、**ブラウザ内で完結するJavaScript**に移植したもの。
サーバー側処理は一切なく、GitHub Pages/Vercel等の静的ホスティングだけで動く
(完全無料方針に合致)。PDFの中身は外部に送信されず、ブラウザ内で処理が完結する。

## 構成

```
pdf-diff-app/
  index.html        画面(ヘッダー・アップロード・ビューア)
  style.css         スタイル
  app.js            UI制御・GASへのログ送信・PDFダウンロード生成
  lib/diff-core.js  差分解析コアロジック(ページ整合/分類/3方式の差分検出)
  gas/Code.gs       記録シート書き込み用GAS Webアプリ
```

使用ライブラリ(すべてCDN経由、ビルド不要):
- [pdf.js](https://mozilla.github.io/pdf.js/) 3.11.174 — PDF描画・テキスト座標抽出
- [jsdiff](https://github.com/kpdecker/jsdiff) 9.0.0 — LCSベースの差分検出(行/文字/ページ単位で共用)
- [jsPDF](https://github.com/parallax/jsPDF) 4.2.1 — 結果を1つのPDFにまとめてダウンロード

## 処理の流れ

1. 新旧PDFをそれぞれ`pdf.js`で読み込み、全ページを描画(Canvas)しつつテキスト座標を抽出
2. ホーム画面で選んだ種類(表/文章/図面)を全ページの分類として強制適用
   (`runDiff`の`forceCategory`オプション)。種類を選ばず自動判定に任せる場合の
   ロジックは`classifyPage`(`lib/diff-core.js`)に残っている
   - テキストが取れない → 図面
   - 行ごとの語数が揃う(グリッド構造) → 表
   - 行が段落状に幅広く続く → 文章
   - それ以外(ラベル・値が散らばる帳票等) → 図面(画像方式で処理)
3. 新旧のページ列を、ページ本文(またはページ内容が薄い場合はサムネイル画像)の類似度で
   LCSベース整列(`alignPages`)。**新版で1ページ挿入された場合でも、対応する旧ページが
   無いページとして正しく「追加」判定される**(挿入位置より後ろの対応関係はズレない)。
4. 対応の取れたページ同士を、分類に応じた方式(表=行/セル単位diff、文章=1文字単位diff、
   図面=ピクセル差分+連結領域検出)で比較し、ハイライトを描画
5. 解析完了時に「日時」「分類」をGAS Web App経由でスプレッドシート「記録」シートの
   2行目に記録(追記後にA2:Bを日時降順に並び替え、常に2行目が最新を維持)
6. 結果はブラウザ上でズーム表示、まとめて1つのPDFとしてダウンロード可能

## セットアップ

### 1. GAS Web Appのデプロイ
1. スプレッドシート(`記録`シート、A:日時 B:分類)を開き、拡張機能 > Apps Script
2. `gas/Code.gs`の内容を貼り付けて保存
3. デプロイ > 新しいデプロイ > 種類「ウェブアプリ」(実行:自分、アクセス:全員)
4. 発行された`/exec` URLを`app.js`先頭の`GAS_API_URL`に設定してpush

### 2. Vercelへのデプロイ
Vercelダッシュボードで Add New Project → 対象リポジトリ選択 → **Root Directory**に
`pdf-diff-app`を指定 → Framework Preset「Other」→ Deploy。
以後はこのフォルダへのpushで自動的に最新版がVercel URLに反映される。

## 既知の制約・今後の調整余地

- **文章方式の文字位置**: pdf.jsのテキスト抽出は「単語/テキスト断片」単位の座標しか
  取れないため、1文字ごとの位置は断片内で均等割りして近似している。元のPython版
  (PyMuPDFの1文字単位座標)ほどの位置精度は無い。
- **ページ分類のしきい値**: `classifyPage`の判定基準(行数・文字数などのしきい値)は
  暫定値。実際の社内PDFで誤判定が出た場合はここを調整する。
- **図面方式のページサイズ不一致**: 新旧でページサイズが違う場合は縦横比を保ったまま
  中央寄せで合わせて比較する(引き伸ばしはしない)。位置合わせ(特徴点マッチング)は
  未実装。
- **ページ整合の類似度しきい値**: `PAGE_SIM_THRESHOLD`(0.5)を下回るページは
  「対応なし」として追加/削除扱いになる。内容が近い別ページを誤って対応付ける/
  逆に対応するはずのページを見逃す、といった誤判定が起きた場合はここを調整する。
